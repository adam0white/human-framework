# Exact cross-arm comparison of the archived baseline

The baseline **does not meet the original strict full-projection bit-equality criterion**. Its tolerance-based comparison did not establish exact full-projection equality.

A new exact audit read every preserved checkpoint in all six driver/restore configurations for each arm in H1–H7. It restores with the archived baseline source and compares scalar values with `Object.is`, without rounding or rewriting any values. All actual Human people, paid ledgers, progress and contribution coverage, latched bases, paid minutes, clock and completion timing, assignments/consent, and physical resources match exactly. The only unequal fields are `.pump.work.hands.<worker>.effort` in the public comparison projection.

The candidate stores accumulated effort, adding `.20 * paidFraction` each actual minute. The direct implementation stores covered fractions and its `inspect` projection derives `.20 * covered`. Floating-point multiplication after addition need not equal addition of individual products. At H1 minute 5, for example, the candidate projection contains `0.05000000000000001`, while the direct projection contains `0.05`. The **actual paid ledger** contains the same accumulated `0.05000000000000001` in both arms.

The direct raw work record has no redundant effort field. This experiment has not added one or rounded either arm to manufacture bit equality. `stages/00-baseline/exact-comparison.json` preserves every differing path, both raw values, minute, driver and checkpoint; `exact-run.json` summarizes first differences. Those repeated checkpoints are diagnostic observations of the same seven prescribed histories, not independent samples. Maximum baseline discrepancy remains `1.3877787807814457e-16`.

The later gasket and two-pump recorders explicitly report `strictFullProjectionEqual` and reject any nonzero cross-arm numeric discrepancy outside the contribution-effort projection fields. Source corrections or a different equality criterion must be considered separately after these two host-only change records.
