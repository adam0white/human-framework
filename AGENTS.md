## Engineering rules

- Stack: TypeScript 7.0.2 (strict, `noUncheckedIndexedAccess`), Vite 8.3.4, Vitest 5.0.5, Biome 2.5.15, React 19.3.1 for UI shells, and Canvas 2D for maps. npm workspaces: `packages/human` (framework) and `apps/site` (games and site). Use Node ≥24 with `/opt/homebrew/bin` first on PATH.
- **Lanes (owner, 2026-10-20, [owner directions](docs/owner-directions-2026-10-18.md)).** Before every commit run `npm run check:lane`: it classifies the changed files by path, the strictest file decides, and runs that lane's checks. Gated (`packages/human`, lab client and kit, the lab Worker, lockfiles and package manifests, CI workflows, deploy and release scripts, Worker and header config) runs the full `npm run check`; delivery adds the build to fast; fast runs lint, typecheck and related tests; prose runs lint. CI runs the full suite on every push and is the source of truth: whoever pushed a red `main` fixes it forward or reverts first. `npm run deploy` requires a green `ci` check on the exact commit instead of re-running the suite. One full local suite at a time on the lab machine (`npm test` takes a machine-wide lock). HF releases keep the full check, the reviews the review rule asks for, the headless control and exact legacy continuation. Measured for a week to 2026-10-27 ([velocity sweep](docs/lab/velocity-sweep-2026-10-20.md)).
- **One worktree per agent.** Work in `npm run wt -- add <repo-dir> <name>` (outside every repo, `node_modules` cloned in seconds), merge to `main` from there; the shared checkout is for the owner and the coordinator. Extracts of other repos go to `~/code/.lab-scratch/`, never into a repo's `scratch/`.
- Keep the actor loop deterministic and independent of LLMs and UI. Person state is plain JSON, and all randomness comes from seeded RNG held in state.
- One owning module per state slice (see docs/framework.md).
- Build first, prove after. A new faculty lands with tests, one headless control scenario, and a short scope paragraph in its module doc comment saying what it covers and what it doesn't. Do not write per-milestone evidence essays or verification JSON. Record negative findings briefly in `docs/findings.md` when they occur. Deferred work goes into [docs/roadmap.md](docs/roadmap.md) (framework) or the game doc's Deferred section (games), with a target.
- **Reviews (owner, 2026-10-20, "Use fewer reviews").** One independent review per change: Codex, or Opus for design calls. Two or more reviews only for an HF release that changes behaviour, or for a new game concept. Owner verdicts and player retests replace extra reviews.
- **Tests (owner, 2026-10-20, "focused/less tests").** Tests stay focused. Each faculty or fix gets tests that pin its own behaviour, plus the headless control. No exhaustive matrices, and no tests that restate the implementation. Where coverage overlaps, delete redundant or slow tests; keep the legacy-continuation, replay-hash and control tests.
- Moral and spiritual faculty: Islam-guided. **User, 2026-10-04:** aim roughly for a post-sectarian, united understanding; where schools differ, take the most common position overall (not only Hanafi), recorded in [research/decisions.md](research/decisions.md). No scholarly review is expected: decide pragmatically within the allowance for a game framework, without contorting religion into a mere game. The framework models modern people's understanding. Keep revealed sources, interpretation, empirical findings and engineering assumptions distinct, with provenance on norm definitions. Never compute divine acceptance, assign quantities to the ruh, or name the RNG or scheduler after divine attributes. Represent a person's *understanding* of a norm, not a ruling. Do not let agents invent rulings; source them from `research/`.
- **Games keep faith gentle (user, 2026-10-04):** the framework stays Islam-guided, but games do not focus on religion. Prayer, fasting and the like appear as quiet parts of a character's life, never the theme, goal or central mechanic. Simulated playtest profiles (e.g. Game 2's naughty players) may push on faith like any other part of a character's life (user, 2026-10-04); that is measurement, not theme.
