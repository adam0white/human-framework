- **Standing direction (2026-10-04):** HF releases are the output; games demonstrate them. Keep framework and games distinct: no game-specific code in `packages/human`, no framework logic in games. Each HF release is a versioned GitHub release, and the released games are upgraded to it (regression test and lesson). Use subagents and workflows liberally, and keep a game-design expert reviewer in the loop for game work. Games stay without action-game polish, real-time graphics or server infrastructure (no Durable Objects, databases) unless the owner lifts that.
- **Game direction (user, 2026-10-04), ambitions, not hard requirements:** the player's read of state stays approximate and subjective (known information, not true numbers); show rather than count (feel ammo, injury, fatigue instead of reading numbers); tactical slowdown rather than hard pauses; continuous game speed like grand strategy, not turns; limits come from capabilities that can change slowly (like action points), not arbitrary caps; saves and menus built on the same fiction. Every game offers a playtest export (seed + input log + state JSON) that replays the player's run.
- **Taste comes from reviews and players:** get adversarial, unbiased and wildcard reviews (different models/personas) on game work, and record playtesters' words verbatim in `docs/games/*-playtest-*.md`; treat them as the strongest signal.
- **Phones:** research real device viewports instead of assuming 360×740 (reference from the 2026-10-04 mobile review: Galaxy S26 360×780 CSS px at DPR 3, about 690 px visible in Chrome, an estimate; S26 Ultra 412×891); use mobile web practice where it helps (fullscreen, input capture, safe areas, wake lock), without turning the work into an action-game UI project.
- The v0 layered-candidate codebase is archived under `archive/v0/` (tag `v0.16-final`). It is provenance, not a work queue, and it is not maintained or built.

## Engineering rules

- Stack: TypeScript 7 (strict, `noUncheckedIndexedAccess`), Vite 8, Vitest 5, Biome, React 19 for UI shells, and Canvas 2D for maps. npm workspaces: `packages/human` (framework) and `apps/site` (games and site). Use Node ≥24 with `/opt/homebrew/bin` first on PATH.
- `npm run check` (lint, typecheck, tests) must pass before every commit.
- Keep the actor loop deterministic and independent of LLMs and UI. Person state is plain JSON, and all randomness comes from seeded RNG held in state.
- One owning module per state slice (see docs/framework.md).
- Build first, prove after. A new faculty lands with tests, one headless control scenario, and a short scope paragraph in its module doc comment saying what it covers and what it doesn't. Do not write per-milestone evidence essays or verification JSON. Record negative findings briefly in `docs/findings.md` when they occur. Deferred work goes into [docs/roadmap.md](docs/roadmap.md) (framework) or the game doc's Deferred section (games), with a target.
- Moral and spiritual faculty: Islam-guided. **User, 2026-10-04:** aim roughly for a post-sectarian, united understanding; where schools differ, take the most common position overall (not only Hanafi), recorded in [research/decisions.md](research/decisions.md). No scholarly review is expected: decide pragmatically within the allowance for a game framework, without contorting religion into a mere game. The framework models modern people's understanding. Keep revealed sources, interpretation, empirical findings and engineering assumptions distinct, with provenance on norm definitions. Never compute divine acceptance, assign quantities to the ruh, or name the RNG or scheduler after divine attributes. Represent a person's *understanding* of a norm, not a ruling. Do not let agents invent rulings; source them from `research/`.
- **Games keep faith gentle (user, 2026-10-04):** the framework stays Islam-guided, but games do not focus on religion. Prayer, fasting and the like appear as quiet parts of a character's life, never the theme, goal or central mechanic. Simulated playtest profiles (e.g. Game 2's naughty players) may push on faith like any other part of a character's life (user, 2026-10-04); that is measurement, not theme.
