## npm

Set up 2026-10-07 (owner: "do npm publishing properly"; then, the same day, "No need to stay secure for this … Agents md can say to publish and store"). The package `@adam0white/human-framework` publishes from `packages/human` (`publishConfig.access: public`; the root package stays private). Releases stay `npm run release` (tag, GitHub release, tarball); publishing the GitHub release starts [.github/workflows/publish.yml](.github/workflows/publish.yml), which checks the tag against the package version, runs typecheck and the framework tests, and runs `npm publish` with trusted publishing (OIDC; the owner configured the trusted publisher with direct publish allowed). No token is needed for that, and npm attaches provenance. A version npm already has is skipped. Rehearse with Actions, "Publish to npm", Run workflow, a tag and dry run on (`npm publish --dry-run`).

First publish: the owner published 2.1.3 by hand on 2026-10-07; it went through npm's staging and is now `latest` (no provenance). A placeholder `0.0.0-stage` from that staging stays on the registry; the owner can hide it with `npm deprecate @adam0white/human-framework@0.0.0-stage "placeholder; install 2.1.3 or later"`. 2.1.4 is the first version published by the workflow, which also validates the trusted publisher (a new one must publish within 2 days). The homepage and README install from npm.

An npm token, if the owner provides one for publishing by hand, lives only in the user's `~/.npmrc` or a GitHub Actions secret, never in the repository, logs or build output.
