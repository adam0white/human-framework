# Private attempt/clock coordination probe: frozen protocol

2026-09-08. Commit this document before executing comparison outcomes. This is a software integration experiment, with no human authoring-time, scientific or theological claim. User-authorized scope is private helpers, adapted consumers, tests and evidence; no released game, runtime, clock, model, package, release lock or asset allowlist changes.

## Question and alternatives

Does a stateless helper remove mechanical authoring obligations from two existing actual hosts without additional host exceptions or greater inclusive source size? The controls are `src/games/watch.js` (Before the Water) and `examples/maintenance-watch/host.js` (the earlier independently authored installed-package consumer). Watch already adapts the maintenance host lifecycle: these are distinct real consumers with differing policies, but their common ancestry limits the strength of a two-host generality claim.

Retaining direct wiring is the control and default. A stateful scheduler that owns new jobs/body/time would add reconciliation and shadow state, so it is excluded. The candidate is a private stateless module borrowing each host's existing `people`, `jobs` and `clock` slots. It starts accepted jobs, interrupts them, validates and completes receipts, and advances the borrowed people/clock to a boundary. It may construct the due-record shape. It must retain no module-level, closure, serialized or second authoritative body/job/clock state. Temporary immutable runtime return values are ordinary calculation, not retained shadow state.

## Interface and boundaries

Candidate `src/coordination/attempt-clock.js` exports `beginJob(state, actor, task, spec, fields)`, `interruptJob(state, actor)`, `completeJob(state, event, {mealConsumed=false})`, `advanceJobs(state, actorIds, target)`, and `dueRecord(actor, job)`. Begin places runtime attempt, clock event and lifecycle metadata in existing host slots, combining explicitly supplied host fields such as reservation metadata. Interrupt and complete return the retired job for host effects. Complete does not restart idle. Advance returns elapsed paid time and due events; it neither applies world progress nor dispatches arrival/events. Functions mutate only the detached draft already owned by the caller; immutable public host entry points remain unchanged.

Host-only obligations remain explicit: recipient choice/refusal, capacity assessment for offered tasks, world prerequisites, parts/food ownership and reservation/refund/consumption, actual paid repair progress, meal receipt authorization, statistics/messages, idle replacement, arrival consequences and first-scheduled arrival precedence, cadence selection, input/save/world validation, and queue/job/person reconciliation. Do not disguise these as generic callbacks. No new host-specific branch in the helper is allowed. Meal consumption is an explicit boolean outcome supplied by the host, never inferred from a task name.

## Predeclared mechanical counts and decision rule

The seven direct-wiring authoring obligations counted per host are: (1) pair beginAttempt with scheduleEvent, (2) copy attempt/event identity and timing into the one host job, (3) pair interruption finish with clock cancellation, (4) compare full due-receipt identity before completion, (5) reject early completion, (6) reject late completion, (7) advance each person by exactly the clock's elapsed interval. Completion's meal outcome and host event dispatch remain host decisions and are not claimed removed. The three receipt exception paths are (4)-(6). The candidate must remove at least four of seven obligations and all three explicit receipt guards from each caller; relocation into the helper is counted separately, never claimed elimination from the total system.

A favorable mechanical result requires ALL of: exact accepted/refused/error-code/state parity for identical histories, zero extra retained state, zero new host-specific helper exceptions/callback protocols, fewer source bytes and nonblank lines in each caller, and aggregate adapted callers PLUS helper bytes and nonblank lines no greater than both direct callers together. Report raw UTF-8 bytes, total lines and nonblank lines, including comments/imports/validation in whole files. Report shared unchanged runtime dependency size separately rather than treating it as free. Use original control source bytes for counts; an isolated import-only normalization of maintenance resolves the same current runtime during comparison, is disclosed, and is not counted as lifecycle simplification. Per-host inclusive size charges the entire helper, as well as the amortized two-host aggregate. If a threshold fails, or a helper only hides host obligations behind new exception/configuration paths, retain the negative result and recommend direct wiring. No automatic package promotion follows even a favorable result.

## Fixed comparisons, assertions and budget

Run both controls and candidate copies through identical per-host command histories. Compare full state and exported JSON snapshots after EVERY command, including receipt errors (code parity plus unchanged caller state). Resume both through JSON at a mid-action point and compare exact continuation. Cover:

- Watch short-notice gate: concurrent repair/lookout, explicit refusals, owned handover, capacity refusal, three paid rest minutes/interruption, final successful repair.
- Watch resources: partial diversion reservation/refund/restart, owned meal partial interruption then full consumption, salvage ownership and duplicate/early/forged receipt rejection.
- Watch arrival ties: equal-time lookout and diversion completion lose to arrival; paid final repair progress counts; terminal commands and saves remain consistent.
- Maintenance: concurrent repair/lookout, role and busy refusal, paid partial repair/refund/restart, full/partial arrival outcomes, solo absence refusal, continued post-arrival idle/rest, exact same-driver mid-action JSON resume, early/duplicate receipts and arrival-first ties.
- Both: mismatched job/person/event/save resources rejected equally; alternate clock drivers evaluated as same-driver control/candidate pairs (the old maintenance host permits tiny person floating-point cadence differences across different drivers, so no new cross-driver exactness claim).

Bound the measured comparison at **10,000 delivered clock events total across both arms and both hosts**. Each event returned by the clock, including arrival and idle receipts, counts; command-only refusals and elapsed boundaries with no returned event do not. Reserve up to 2,000 events for fixed histories and spend the remaining even budget on identical maintenance post-arrival histories in both arms, stopping at or before 10,000. The runner must abort rather than exceed its budget, report actual delivered event count and elapsed boundaries, and retain exact final full-state hashes. This is a bounded mechanical parity/state-size workload; elapsed desktop process timings are descriptive and exclude UI, rendering, network, humans and physical devices. No success/runtime-speed threshold is invented after measurements.

Evidence CLI requires one explicit fresh output path and exclusive creation; failed execution must never overwrite a retained artifact. Verify protocol bytes against its full resolved commit, list source hashes and record Node/platform/CPU/source identity. Retain original evidence unchanged, and label any later corrections as separate files.
