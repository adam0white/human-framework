# Next bounded experiment: what an offered action promises

Selected after app 0.14, 2026-09-08; now completed as a [private study](action-offer-results.md). The corrected candidate is retained privately and the production gate remains unchanged. This is a small host/interface experiment, not a new capability module, a new game requirement, or a rerun of the completed physiology comparisons.

## Observed cost and current uncertainty

Across's work and report controls conservatively assess the upper edge of the actor's rounded body estimate. That avoids offering an interval the actual host will reject, but can hide legal work. The already identified keeper fatigue .9751 / hunger .15 case displays fatigue 1: Inspect is unavailable in the view, while the actual one-minute inspection is admitted and completes with .9796 fatigue. Root reproduced this exact case; [exploratory record](../artifacts/release-0.14/next-offer-counterexample.json). It establishes avoidable waiting in the offer, not lost service or worse player understanding.

Camp's current offers already use authoritative own-body admission, so it is a useful contrasting consumer and negative control. Do not assume both need the same mechanism. Own capacity refusal and hidden remote knowledge are different boundaries.

## Pre-outcome protocol

Before a new evaluation, commit a small exact input set and chosen offer variants. Use released Human/runtime 0.1.1 and unchanged host admission, payment, reservations, stopping and replay. Include:

- Across's legal-but-hidden inspection plus a nearby actually impossible interval.
- Whole-job versus one-minute repair near a capacity boundary.
- A valid near-deadline continuation capable of testing whether an extra wait changes the outcome; preserve no-effect results rather than retune a deadline to manufacture benefit.
- Camp controls where current offers already agree with actual admission.

Compare the current conservative offer with **estimate uncertain; let the player try**. Keep actual host validation authoritative. A try control may produce a clearly explained, unchanged-state refusal; it must not label uncertain admission as guaranteed. Do not have rendering or policies repeatedly dry-run hidden state to infer extra information. Keep actor-local views and the remote-world indistinguishability checks intact.

Record legal work hidden, avoidable waiting, explicit refusals, paid work/body/resources, and service or project outcomes separately. No weighted synthetic score or claim of human clarity follows automatically. If UI is changed, verify the exact offered/uncertain/blocked wording and controls through real browser actions. Keep the old source/results and source-pin any new outcome set.

## Decision and stop rule

If the simpler try control resolves a meaningful demonstrated cost, retain it as a small host/UI convention. Shared code requires actual necessary duplicated logic or independently demonstrated authoring value across both consumers. If no meaningful consequence or clarity benefit appears, retain the current gate and close the investigation. Do not add a general capability, planner or body model to rescue the premise. This follow-up does not block the completed app 0.14 release.
