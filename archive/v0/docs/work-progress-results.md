# Paid durable work: tested reuse, no promotion

Completed 2026-09-08. Keep work candidate 0.1.1 private. It embeds independently and passes the corrected accounting checks, but this experiment does not establish a worthwhile maintenance reduction over direct host code. The portable runtime remains Human/runtime 0.1.1 plus clock 0.1.0; no new general human faculty is claimed. All 69 delivered app payloads remain byte-identical and nine new private/retired paths return 404; app 0.12 stays at its verified source rather than being redeployed for private research. ## What was built and what was compared

A dependency-free item component owns physical progress, each worker's latched basis and paid contribution, and bounded completion status. The host still owns people, capacity, assignments and consent, clock progression, earned tools, resources and output settlement. [Frozen API](work-progress-api.md) · [Declared proposal](work-progress-proposal.md) · [Concrete scripts and amendments](work-progress-execution.md).

The API and protocol documents remain byte-preserved freeze inputs; any pending-stage wording in them describes their declaration time, superseded by this completed report.

Separate authors implemented a complete camp-shaped candidate consumer and competent direct prospective/fixed rivals without reading one another's new source. After the actual interface freeze, a fresh author built a pump-repair consumer using only a copied package/API and Human documentation outside this repository. The two independently authored host contexts use different world schemas and material rules but the same prescribed work law. This is a narrow engineering integration test, not a sample of independently discovered game needs.

| Prescribed history | Candidate/direct prospective completion | Smaller fixed contract |
|---|---:|---:|
| Unchanged work | 20 | 20 |
| Paid tool arrives at minute 1 | 15 | 20 |
| Stop at 7, recover to 10, resume | 23 | 23 |
| Tool plus zero-time stop/resume | 15 | 20 |
| Faster worker accepts at 1 | 19 | 20 |
| Slower worker accepts at 1 | 20 | 18 |
| Busy recipient refuses | 20 | 20 |
| Two items: starts at 0 and 2 | Both 20 | Both 20 |

Every arm completes its prescribed output by the common minute-40 endpoint. Endpoint fatigue has recovered to zero, so retained intermediate body state, paid effort, task practice and ownership are essential to interpreting the differences. The fixed contract is sufficient in several cases and faster when it retains the more proficient worker. Timing differences between prospective/fixed laws do not measure abstraction quality.

The camp has eight histories × three arms × three drivers × with/without active restore = 144 configurations. The independent baseline has seven histories/84 configurations, later eight/96 after adding a second pump. Repeated drivers, versions, checkpoints and stages are not independent empirical samples.

## Cost and adoption decision

| Corrected runtime source boundary | Candidate bytes | Direct bytes |
|---|---:|---:|
| Camp, including actual static dependencies | 43,206 | 40,678 |
| Independent two-pump consumer | 55,611 | 51,171 |
| Both consumers, identical shared sources counted once | **72,791** | **72,505** |

The aggregate is almost source-neutral: candidate adds 286 bytes while using 15 fewer nonblank lines (978 versus 993). Do not add the two per-consumer premiums: that double-counts the shared component. Nor does either byte or line count measure human authoring effort. The exact source inventories count host validation, adapters and common Human/model dependencies. Test/recording/measurement code is reported separately. [Combined accounting](../artifacts/work-progress/combined-cost.json).

The candidate centralizes one work invariant, and the two-pump adapter needs a little less change than the direct version. Most required implementation and validation remains in both hosts; gasket handling changes equally. The direct camp retains a stronger historical skill-basis check, while the generic candidate has broader standalone/16-worker scope than the repair host needs. Neither unequal assurance nor extra capabilities are counted as demonstrated benefit.

All measured camp arms satisfy the predeclared 5 ms p95 budget (approximately .168/.117/.127 ms for candidate/direct/fixed). The corrected timing process overlapped the behavior matrix; these descriptive local measurements establish budget feasibility under that load, not causal speed superiority or physical-device performance. The exercised two-item/16-contributor component shape uses 6,193 JSON bytes within 8 KiB; it is not a worst-case proof. [Exact measurement scope](../artifacts/work-progress/camp-corrected/MEASUREMENT.md).

**Decision:** preserve the corrected candidate and direct references privately; do not add the component to the runtime/public build. The experiment demonstrates reuse with near-neutral source cost, but neither convincing maintenance savings nor the complete predeclared equality gate. A real later need may justify returning to it; constructing extra consumers merely to amortize it would not.

The next milestone is a smaller maintained Camp consumer that retires obsolete compatibility/journal obligations under an explicit current-state contract. That changes assurance/functionality deliberately, so its savings cannot be credited as equally strong validation becoming cheaper. [Next bounded proposal](camp-maintenance-proposal.md).

## Reproduce and inspect

Use a fresh output path. Historical frozen inputs can be read from their named Git objects; the selected current corrected files remain hash checked by the comparison runner.

    PATH=/opt/homebrew/bin:$PATH node scripts/work-progress-comparison.js run --freeze artifacts/work-progress/freeze-camp-corrected.json --out /tmp/new-work-runs.json.gz
    PATH=/opt/homebrew/bin:$PATH node scripts/work-progress-comparison.js replay --input /tmp/new-work-runs.json.gz --out /tmp/new-work-replay.json
    PATH=/opt/homebrew/bin:$PATH node scripts/reproduce-work-repair.js

The last command materializes all required source and losslessly compressed evidence in a fresh temporary directory, installs only the local kit offline with scripts disabled, then executes the final 61 consumer tests with directory-only Node filesystem reads. Manifests retain original and stored hashes for compressed files.
