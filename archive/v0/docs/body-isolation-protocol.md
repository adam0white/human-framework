# Preregistered body-structure isolation

Registered 2026-09-08 before implementation or new-arm outcomes. This new private software study preserves the earlier [mechanism comparison](mechanism-comparison.md), its protocol, sources and reports unchanged. Its purpose is deciding whether a small game needs separate food/rest bottlenecks. It is not human evidence, a physiology claim or a new shared runtime.

## Fixed models and analytic predictions

Compare released Human 0.1.1 against pooled stamina with **the identical frozen `practice()` function**, `s + (1-s)*(1-exp(-0.0052*t))`, and one current proficiency scalar per skill in both. No retained initial proficiency or accumulated training counter belongs to the pooled model. Pending attempts retain the single practiced skill's baseline for validation/resume; host cumulative exposure is common measurement bookkeeping. No learning coefficient sensitivity is allowed.

Map body to `stamina = 1-(2*fatigue+hunger)/3`; success load is `2.4*(1-stamina)`, matching Human's `1.6*fatigue+0.8*hunger` at initialization within 1e-12. Pooled maintenance drains 1/600 per minute, work drains an additional `(2/3)*effort*elapsed/duration`, rest adds 1/60 per minute, completed owned meals add 11/60. Pooled stamina clamps to [0,1]. To remove the earlier incidental meal-order asymmetry, completed pooled meals calculate from the attempt baseline including the full paid maintenance before relief and clamping, as Human does. This is a declared new rival, not a change to old evidence.

From a mapped state, Human admits work iff `F+0.0015*t+effort <= 1+1e-12` AND `H+0.002*t <= 1+1e-12`. Multiplying these bounds by 2/3 and 1/3 gives the pooled requirement `1-S+t/600+(2/3)*effort <= 1+1e-12`. Therefore nominal pooling is analytically no stricter at mapped states (allowing floating tolerance). Human-blocked/pooled-admitted cases are expected by design; more expected output from them is no human-performance victory. Later states may no longer map because pooling permits different admissions and recovery/clipping differs. Record those paths rather than extend the proof to unmatched states.

At equal admitted task exposure, proficiency must match within 1e-12, including partial attempts. Any residual forecast/output gap must be decomposed into body-load difference, admitted exposure and clipping; there is no learning-curve explanation left. Saturating practice's composition property implies chunking agrees numerically, not necessarily bitwise across different floating arithmetic groupings.

## Common host, controls and matrix

The complete [condition matrix](../artifacts/body-isolation/protocol.json) is committed with this document before code/results. Existing schedules are retained as known diagnostic controls. Their historical Human/linear-counter results have already been seen; only the new pooled-saturating outputs are withheld. “Reserved” means new-arm results executed after a committed source freeze; it does not mean blind or independent unseen conditions. Four newly authored choice conditions add equal-load hungry/fatigued starts, each offered either rest 20 or meal 10 + idle 10, followed by work 20. Both routes cost 40 minutes and own one ration/three parts initially. The meal route spends a ration; rest retains it. A choice earns separate body state only if the two mapped starts require different feasible recovery routes; then player understanding/usefulness still needs play evidence.

Host actions, time, initial resources, output rule, work part debit, meal receipt and interruption contracts match the frozen comparison exactly. One model-neutral controlled host serves both new arms. The old module closes over its adapter registry and has no dependency injection; duplicate its host lifecycle into the new scope rather than mutate the registry or frozen code. Count the duplicated host as common source cost, not free authoring. Reuse its exported schedule decoder/comparison function through a nonmutating import when practical. Regression comparison against the frozen Human host must show unchanged Human trajectories.

There is no controller, hidden state, per-condition parameter tuning, free recovery, free washout or random success. Expected output is ten times the start forecast only for completed admitted work. Capacity/resource refusal occupies the prescribed interval as maintenance-only time without practice or output. Interrupted work retains paid exposure and spent parts; interrupted meals give no food relief or debit. Every A/B/idle exposure uses 120 minutes, rest 40 and owned meal 10; independent paid 10-minute A/B retests follow. Keep A/B effort/body paths equal within each model. Report actual admitted training and task specificity, not requested time as practice.

Sensitivity repeats every condition with pooled recovery effectiveness 0.75 and 1.25; all Human coefficients and both practice updates remain fixed. These are robustness disclosures, not tuning candidates. Operational tolerance is the previous predeclared 5% offered-output gap, 0.03 mean jointly-admitted work forecast gap, identical step admissions/resources, plus 0.03 and identical admission for each retest. Preserve smaller-model agreement, near-threshold cases and all divergent trajectories; no aggregate winner or p-value.
