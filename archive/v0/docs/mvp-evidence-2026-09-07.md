# A more credible portable-kit MVP

Work begun 2026-09-07 while Common Ground was being playtested. This milestone tests reuse, comparison quality and lifecycle correctness. It adds no new public game and preserves the current games' mechanics.

## What changed

**A new author consumed the actual package.** The headless maintenance/watch example coordinates a 12-minute repair, an 8-minute lookout and an arrival at minute 18. It handles owned parts, interrupted work, independent refusals, solo play and saving mid-action. Its unchanged files run in a separate installed consumer that is denied repository reads. The author recorded missing documentation and integration mistakes, so this is more informative than a same-author transplant. It is independent authorship, not blind onboarding. [Consumer and measurements](independent-consumer.md).

**The controller comparison now preserves tradeoffs.** Thirty-six development trials and twelve reserved trials use the same frozen Common Ground world and public observations. From a fresh cooperative start, build-first establishes the worksite at minute 220; the new project-focused rival does so at 214. But after a 240-minute delayed start, stock-first needs 242 additional minutes and the rival 248. In another reserved case the rival finishes sooner yet produces 25 later caches versus build-first's 26. All 48 reach the first milestone by the full 1,440-minute budget; shorter checkpoints retain unfinished outcomes. These are comparisons of host controllers, not laboratory Full or different body models. [Full results and registration](commons-comparison.md).

**The social abstraction did not earn promotion.** An addressed proposal/response/commitment record works in two miniature hosts, but direct rules match its outcomes while saving less state. Sixteen thousand attempted commands produce no outcome, resume or mutation mismatches; 10,000 settled/discarded contracts leave no retained history. The shared version's larger snapshots are a cost, not a benefit. Keep this candidate private and experimental. It records agreements; it does not explain a person's reasons for accepting them. [Probe and direct rival](social-contract-probe.md).

**The runtime boundary is more dependable.** Human/runtime 0.1.1 fixes reordered pending-save fields and fractional-time bookkeeping. Explicit import migrates valid 0.1.0 records; it rejects already inconsistent history. The old human implementation, clock, equations and current games remain frozen. Packaging now rejects changed source under a released component version, including a changed transitive formula or an unversioned change to the runtime's component combination. The API document now specifies the complete host-facing lifecycle and save contract. [Compatibility patch](human-compatibility-patch.md) · [Installation and API](portable-runtime.md).

Two separate Claude Fable reviews and Astra cross-reviews supplied concrete corrections. We also followed up three historical learning-source leads and corrected stale coverage statuses. No additional human faculty or empirical coefficient was adopted. [Review decisions](reviews/2026-09-07-evidence-review.md) · [Source follow-up](../research/learning-source-followup-2026-09-07.md) · [Cooperation evidence and boundaries](../research/cooperation-boundary.md).

## What this changes in the roadmap

External installation and host lifecycle have stronger evidence. The next model-value test is a prescribed-action comparison against a smaller stamina/practice-counter implementation. The next reuse question is whether a thin clock/attempt helper reduces repeated host bookkeeping while preserving ownership and interruption rules. Both come before expanding the faculties.

Your current playtest remains the best input for clarity and worthwhile choices. The five-person explanation gate, measured authoring benefit and physical-mobile timing remain open. A playable repair/lookout/arrival slice is a bounded route toward cooperative defense after the package and choices prove useful. [Updated graduation checks](mvp-contract.md).
