## Preserved reviewer corrections and limits

The first core readiness assertion expected recovery after two minutes. Its own arithmetic was wrong: timber requires `.13 + 16 × .0015 = .154` fatigue capacity, and the chosen `.95` starting fatigue needs five `.0235` recovery increments. The corrected independent probe checks minutes zero through five and confirms `player-ready-for-work` at five. The original failing assertion/output and the [corrected arithmetic result](../../artifacts/release-0.13/reviews/core/camp-current-core-readiness-corrected-output.json) remain preserved. This was not an application finding.

The first UI harness checked an asynchronous import message too early and waited for a Work button to become visible while the correct checkpoint panel hid Work. It was corrected to wait for the message and button attachment. [First harness results](../../artifacts/release-0.13/reviews/ui/first-harness-results.json) remain alongside the completed run. The browser's initial loopback port was unavailable and the reviewer started the repository's development server; that is recorded setup, not a production outage.

The original UI run covers ten main groups and four follow-up groups: phone/desktop and short-height layouts, keyboard tabs and Meryem requests, paid work/stop/reload, the isolated current storage key, real downloads, import preview/confirmation/cancellation/races, checkpoint/dispatch/return consequences, quota and corrupt/read-denied storage protection, and Save-and-leave download recovery. Its screenshots were inspected by the reviewer. The corrective pass was deliberately narrow: restored/imported ferry status, returned cache hint and partially paid returned-cache card. It did not repeat the broader matrix. No console warnings/errors or external network requests were observed in the recorded browser runs. These were installed desktop Chrome/Playwright headless checks, not physical-phone Safari or real screen-reader validation.
