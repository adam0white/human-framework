# Across action-offer candidate contract

**Retained private candidate; not the active app API.** Reviewed source is frozen at `41430e89c6402ff149e092261bfd81ab15a30aa5` and preserved in [the candidate archive](../artifacts/action-offers/candidate-source.json.gz). The [completed study and nonpromotion decision](action-offer-results.md) keep the production gate unchanged. Candidate for the [bounded action-offer experiment](action-offer-proposal.md), 2026-09-08. This is an additive host/interface convention. Its comparison and delivery decision are separate from these unit regressions; a passing contract does not establish a service benefit or player understanding.

`getGameView(game).choices` retains each existing choice and its conservative `unavailable` string or `null`. Every choice additionally has `capacityUncertain: boolean`. The bit is true only when the upper edge of the actor's rounded body estimate fails the requested interval **and the lower edge passes**, after the ended, current-job, own-decision-budget, station, known-work and owned-supply prerequisites have passed. Human 0.1.1 presents each body value in bins of .05; these edges are the displayed value plus or minus .025, clamped to 0–1. If even the lower edge fails, the interval remains disabled with its existing capacity explanation and `capacityUncertain: false`. A structural refusal also always has `capacityUncertain: false`. The classifier receives only the detached keeper view; it neither inspects the raw body nor attempts host admission.

`web/across-view.js` exports `reportOffer(view, count, via)`, returning `{ unavailable, capacityUncertain }`. Its structural checks cover the ended shift, current task, selected-observation count, own decision reserve, radio charge and local contact presence before checking both edges of the one-minute sending estimate using the same rule. The existing `reportUnavailable(view, count, via)` remains a string-or-null wrapper. For a simultaneous report supply/contact and estimated-capacity failure, the structural reason now takes precedence. Existing message text remains intact.

| Classification | `unavailable` | `capacityUncertain` | Candidate presentation |
|---|---|---|---|
| Conservative offer | `null` | `false` | Ordinary action control |
| Estimate bin permits both admission and refusal | Existing capacity-estimate explanation | `true` | Explicit uncertain Try control |
| Entire estimate bin cannot support the interval | Existing capacity-estimate explanation | `false` | Disabled control with its reason |
| Structural block | Existing structural explanation | `false` | Disabled control with its reason |

Presentation reads the boolean and does not infer this distinction by parsing English. “Uncertain” means the available estimate does not settle admission; it does not promise that the attempt is legal. The actual `applyCommand`/host request remains authoritative. A capacity refusal throws the existing `CAPACITY` error without changing the game, paid time, decisions, inventories, receiver state or saved command recipe. Trying is an explicit player request; rendering and policies do not repeatedly dry-run host state.

The player driver continues to use its existing conservative strings for `capacity-available` stop detection. `run`, `stopReason`, clocks, command application and all physical transitions are unchanged. Player 0.1.0, receiver 0.1.1, host 0.2.0 and Human/runtime 0.1.1 keep their existing identities. Recipe fields, accepted commands, save versions and replay behavior remain unchanged; metadata is derived during view construction and is not stored. Camp is unchanged and remains the contrasting consumer whose existing offers already use actual own-body admission. No shared capability module is introduced.

The focused contract tests cover the previously known .9751 inspection and the .9956 impossible counterpart with the same visible estimate; whole-job versus one-minute repair; definitely impossible full repair and travel with valid one-minute counterparts; hunger twins on opposite sides of actual admission; structural work, supply, budget and contact guards; detached-view immutability and hidden-remote twins; exact unchanged-state host refusal for inspection and reserved-radio transmission; the old inspection recipe's exact host/receiver state; and the existing `capacity-available` stop. Released host, receiver, Human and clock bytes are checked against the retained Across reviewed source freeze. The legacy driver and session tests remain applicable.

Before the candidate implementation, the new contract suite had nine expected missing-API/metadata failures and two passing compatibility controls. The first implementation passed all 40 focused tests. Independent review then identified that an upper-edge failure alone can include intervals impossible throughout the bin. Two added regressions failed on that classification before the lower-edge check, while the hunger-twin preservation regression passed. After correction, `node --test tests/action-offer-contract.test.js tests/across-player-driver.test.js tests/across-session.test.js` passed all 43 tests. These are bounded unit/compatibility regressions, not results from the preregistered comparison matrix. The old recipe hash was recorded from the unmodified driver before this change.

The current contract test harness reconstructs this exact frozen candidate graph before executing its fourteen checks; it does not install the candidate in active public modules. Historical freeze inputs and original candidate tests remain in the source commit/archive.
