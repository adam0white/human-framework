# Sustained person across ordinary days

The user authorized substantial autonomous progress toward the full framework after Three moments, with further games deferred. This selects roadmap stages 2 and the retained-learning part of 3: continuous daily condition, acquisition and later access, and continuing obligations in a reusable private candidate. It also requires an independent second consumer and meaningful simpler controls, so delivery is more than a new mechanism or scenario.

## Architecture and scope

Keep Human/runtime 0.1.1, situated-person 0.1.0 and public app 0.15 byte-identical. Add private `src/development` modules and a separate sustained-person 0.1.0 package. Compose existing actor-local purposes, observations and canonical commitments. New condition rules must have one owner; don't apply both old minute coefficients and new day-scale coefficients to the same interval. Model every elapsed minute explicitly as waking activity or sleep; food needs a consumed resource receipt. Persist mid-interval without free work, rest, practice or fulfillment.

Retained access is separate from the historical truth that instruction was received and from practiced motor/task skill. New learning requires attributable, paid evidence; time alone cannot teach an item. All rate/threshold values are authored engineering parameters, not calibrated physiological or psychological findings. No universal age penalty, spiritual score or fabricated empirical accuracy.

A connected headless multi-day host integrates learning, household/service obligations, work and independent recipient responses. Equal-time controls remove learning reinforcement, shorten sleep, withdraw a responsibility, and change an unseen event without communicating it. Preserve simpler sufficient alternatives and compare projections honestly. A second independently authored consumer installs only the new package with repository access denied.

## Acceptance

- Continuous multi-day condition affects later actual attempts and can recover without resetting identity/history.
- Delayed retrieval changes with paid learning history while source facts remain attributed; no arbitrary transfer.
- Same world timeline under coarse and minute drivers agrees within declared numerical tolerance; interruption and JSON resume agree.
- Commitments and resources have canonical host ownership; observation is required before actors react to a hidden event.
- Independent consumer, package allowlist, rejected malformed snapshots and full regression suite pass.
- Record exact source hashes, reproducible comparative results, review dispositions and remaining gaps. Push private delivery and handoff; preserve the separately verified public app without a cosmetic redeployment.

## Alternatives

Repeating the episodic showcase leaves continuous life absent. Replacing every existing kernel at once makes failures hard to attribute. A separate compositional candidate makes the new behavior testable while preserving current releases. A constant-recovery/no-decay rival remains an explicit sufficient baseline where it matches the richer candidate.
