# Experience, attention and inference

The user authorized several rounds of framework progress followed by a fresh subagent round proposing small games. This selects three engineering rounds; no game implementation or broad human validity is claimed.

1. **Experienced episodes:** actor-bound episodes preserve event occurrence, delivery, context, source, action/outcome and attributed boolean observations. Deterministic context retrieval returns bounded historical episodes with original times; retrieval cannot turn an old report into fresh evidence. Explicit correction/retraction and duplicate handling preserve provenance. An experience query changes a later method in a host with a persistent route hazard; absence, unrelated context and expiry are controls.
2. **Attention and inference:** a bounded delivered inbox distinguishes receipt from processing. Explicit selected message processing consumes an actual completed review attempt; unavailable/unread/expired messages do not become beliefs. Logical inference uses finite authored conjunction rules over the actor's current conservative belief view; derived results retain supporting proposition/rule IDs, propagate conflict conservatively, retract on changed support, and never mutate original evidence. These remain symbolic candidates, not calibrated cognition.
3. **Reusable integration:** an optional experience workspace is paired with the existing adaptive person through explicit operations, not edits to frozen components. One existing actor clock/body owner; paid receipts derive from actual Human attempts. Hosts own canonical worlds and separately attest messages/outcomes. Package only declared source; independently install into another application with repository access denied. Test mid-action save/restore, alternate command ordering where allowed, error atomicity and simple direct policies. Demonstrate the same components in a route/work host and independently authored non-game application.

Prefer isolated components plus a small adapter over expanding the existing monolithic state or introducing generic plugin registries. API changes remain in a new private experienced-person 0.1.0 candidate; existing Human/runtime and every prior candidate remain byte-identical. No added dependencies, browser globals, LLM calls, hidden filesystem access or public assets. Schemas are data-only, finite and deterministic, with explicit exhaustion behavior. Export functions return detached data. A host-provided snapshot is structurally checked but not authenticated history.

Game readiness here means these bounded capabilities integrate and survive independent use; the complete human framework remains unfinished. After verification, fresh agents will each propose a tiny game tied to delivered mechanisms, with one coherent player loop and a clear scope limit. Ideas are documented, not built in this task.
