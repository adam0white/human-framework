How the lab handles what you send

The games on adamwhite.work send two kinds of things to the lab. Both go to one endpoint on human.adamwhite.work and are stored in a private storage bucket. Updated 2026-10-19.

1. Anonymous play events

Small, batched, and sent in the background while you play. Each batch holds only these fields:

FieldExampleWhy
gamepasswhich game
session id 16 random letters and digits to join the events of one visit. It is made at random, kept only in this tab’s sessionStorage, and gone when you close the tab. It is not a cookie and is not derived from your device.
eventsstart; “service 3 done”; screen “night 2”; end. Names are fixed by the game; the server drops any name with an address or link in it.where people stop, what they reach
timemilliseconds since the session startedhow long a visit lasts
errorthe type and place of an uncaught error, such as “TypeError at index-3f2a.js:12:345”, never its message; at most 5 per visitto find broken builds
buildcommit 01601bc, HF 2.8.0, game 0.1.0which build you played
viewport classphone, tablet or desktop (from the window width only)to know if phones work

The server adds one thing: the hour it was received (for example 2026-10-19T14). Nothing finer.

Never collected: your name, email or account; cookies; IP address; user agent; location or country; screen size in pixels, fonts or any other fingerprint; what you type.

Turned off when your browser sends Do Not Track or Global Privacy Control (checked in the browser and again on the server), when you untick “anonymous play events” in a game’s send dialog (remembered in that game’s localStorage), and on localhost.

Kept: raw batches are kept about two days. They are then folded into daily counts per game (sessions, durations in five bands, milestone counts, last-screen counts, error counts, viewport classes, builds) and deleted. Session ids do not survive that step. The daily counts are public on the lab page and in /lab/data.json.

2. A run you choose to send

Some games have “Send this run to the notebook”. Nothing is sent until you press Send. The dialog shows the exact text first. It holds:

  • the game’s own playtest export: the seed, every input you made with its game time, and the game’s state, which is what the game’s “download run” button already saves;
  • an optional note, in your words;
  • an optional “who you are” label, such as “owner” or “a friend of Adam” (the dialog does not remember it);
  • the build, as above.

It is compressed in your browser (gzip) and stored privately. Runs and notes are never published, on the lab page or anywhere else. The people building the games read them, replay them and quote short lines from notes in the lab’s feedback ledger only when the line is about the game and has no personal detail. The note is free text, so please do not put personal details in it.

After sending you get a reference like r-abc123defg. Nothing else ties a run to you, so quote that reference (or the time and the label you used) to have a run removed: open an issue at github.com/adam0white/human-framework or tell Adam. Runs are kept until then or until the lab no longer needs them.

A run can be at most 2 MB compressed (8 MB uncompressed). A few runs a minute are accepted from one place, and at most 200 a day in all.

What else touches your visit

  • Cloudflare serves these sites. To answer any request it sees your IP address, as every web host does. The lab code uses the address only, in memory, to limit how often one place can send; it does not store or log it, and Worker request logs are off.
  • human.adamwhite.work (and possibly the game sites) load Cloudflare Web Analytics, a separate cookieless page-view counter. That is not part of the lab and is not described above.
  • Fonts come from Google Fonts.
