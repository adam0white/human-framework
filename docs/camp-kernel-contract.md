# Camp kernel 0.2.0 / save 2

This separately selected host is `src/games/camp.js`; original Common Ground and its saves remain unchanged. It uses released Human/runtime 0.1.1 and clock 0.1.0. Coefficients remain authored software choices.

## Public interface frozen for parallel implementation

All calls are synchronous, pure and return detached state/view objects. Invalid input throws without changing the caller. `CAMP_VERSION = '0.2.0'`; `COMMONS_VERSION` aliases it for familiar adapters. `PROJECTS` retains the original Common Ground definitions.

- `createGame({solo = false, improvement = 'prospective', recovery = 'automatic'} = {})` creates the familiar actual Common Ground opening using the new Human version. Controls are `improvement: 'snapshot' | 'prospective'` and `recovery: 'active-idle' | 'automatic'`.
- `startJob(game, id)` starts the player's `gather-timber`, `gather-salvage`, `forage`, `eat`, or `build-shelter/workbench/garden/cache` job. A build resumes the existing physical stage when one exists. There is no finite rest job: automatic available-time recovery needs no assignment. In the active-idle control `startJob(game,'rest')` selects available-time recovery until a new player job (a zero-time, preemptible mode, not a fixed rest attempt).
- `cancelJob(game)` immediately stops the player's job. Installed assembly material and fraction remain at the worksite; a fixed gather returns no output; an interrupted meal returns its own portion without relief. `requestProject(game, project)` and `releaseProject(game)` retain the original consent/commitment vocabulary. Release stops project work, preserving durable assemblies, but does not cancel Meryem's own meal or food collection.
- `requestHandover(game, from = 'player', to = 'neighbor')` requests transfer of the currently assigned physical assembly. The recipient must be free and have capacity. Meryem additionally refuses hunger/recovery need or a conflicting accepted project, and independently accepts a compatible project. Selecting a request from Meryem to `player` offers relief; Meryem accepts release of her currently accepted project stage only when the player is free and capable. A refusal records `lastResponse` and leaves work/assignment untouched. No call directly orders an arbitrary Meryem job.
- `advanceGame(game, minutes)` advances 0–1440 whole minutes per call. There is no 240-minute campaign ceiling. `advanceToNextEvent(game)` advances to a real completion, recovery floor/readiness boundary, or a finite six-minute review interval when nobody is assigned; assigned work scans to its earliest completion unless actual recovery or readiness gives an earlier boundary. Whole-minute stepping makes caller chunks equivalent.
- `getGameView(game)` returns `version`, `solo`, `now`, `stock`, `structures`, `caches`, `milestoneAt`, `people`, `commitment`, `lastResponse`, `recent`, `choices`, `nextEventAt`, `stats`, plus `options`, `work`, `lastAssemblies`, `paid`, `migration`, `nextStop`. Person views retain `body`, `skills`, etc. and `job: null | {id,label,project,startedAt,endsAt,duration,remaining,cost,workId,progress}`; `availableActivity` explains automatic recovery/active idle. Choices retain `id,label,detail,duration,cost,output,project,unavailable`. Admission uses actual body consistently with execution; displayed body remains an estimate. `nextStop = {at,reason}` is always finite before the numeric world limit. `work` contains only current unfinished stages keyed by project; each includes progress, material, per-worker duration basis and paid contributions. `lastAssemblies[project]` retains the most recently completed full receipt with worker contributions; only four receipts can persist. Completed totals remain in structures/caches/stats, so repeated caches do not grow active state. `paid[actor]` separates work/recovery/idle/meal minutes, plus effort and construction/gathering practice minutes since the origin.
- `exportGame(game)` yields `{format:'human-camp',version:2,game}`; `restoreGame(snapshot)` validates and returns the new state. This is deterministic snapshot continuation with bounded recent receipts and active work, not a claim of complete historical command replay. Save format, Human and clock versions, work ownership, reservation/material conservation, totals, actions, pending timing and finite bounds are checked.
- `migrateLegacyGame(snapshot, options = {})` accepts an original `{format:'human-common-ground',version:1,game}` snapshot only after its original host validates it. The actual original snapshot remains under `game.origin`; `view.migration` reports source version/time and conversion. People migrate through the released Human importer without changing body, skill, minutes or identity. Active gathers/meals keep pending action, duration, output, reservations and due event until completion. Active assembly receives exactly its paid fraction and per-worker duration basis; future work uses the selected productivity rule. Already-canceled legacy work cannot be recovered. Active legacy rest is explicitly interrupted into immediately available recovery with all paid recovery/body/skill retained. Old completed caches retain their aggregate count and absence of individual creation timestamps. Original clock identity/counter is preserved; converted assembly/rest events are canceled explicitly. Accepted project intent survives migration; Meryem's controller first runs on a subsequent command or paid minute, so migration itself grants no new work or food.

## Physical and social rules

One stage owns one reservation. Each worker keeps the skill-duration basis from their first assignment to that stage; repeated stop/resume cannot refresh skill or snapshot-tool bonuses. A replacement supplies their own basis and pays only future fraction. A completed workbench changes prospective productivity from the following paid minute; all actors use beginning-of-minute structures, and tied completion effects settle before the controller runs. No historical exertion/practice is refunded. Final-minute effort is proportional to remaining physical work; construction practice follows actually paid runtime minutes.

Meryem pursues one accepted project, obtains missing material, and independently chooses a meal or available-time recovery when actual capacity requires it. Available recovery never produces food. Default unassigned time is low-demand recovery; the active-idle control retains a separately selectable recovery mode. A request is not a promise of immediate exertion. All future time remains pausable by the application.

Active state uses bounded current work, aggregate receipts and sixteen recent messages; saves never accumulate a campaign-sized command journal. Numeric limits retain stop/export, and time advancement remains admitted independently of how many requests have occurred. Strict JSON traversal rejects cycles, repeated references, accessors, oversized inputs and nonfinite values before expansion.
