# Next bounded implementation preflight: practice and useful work

The [completed empirical pilot](learning-pilot-results.md) supplies no warranted runtime coefficient or replacement curve. Return to an actual software-design question already identified in [Learning through useful work](../research/learning-through-work.md#incentives-and-remaining-risks): does paid practice reward withholding useful completion, and does the current interface explain a meaningful later benefit? This is an authored-game incentive check, not another human-data fit or a claim that all purposeful training is wasteful.

Current [Camp 0.3](../src/games/camp-current.js) credits permitted minutes in gathering/construction. Proficiency changes later fixed-job durations through `floor(skill*4)`; assembly retains each worker's initial basis and applies actual later workbench improvements prospectively. Successful useful work and paid interruptions both supply practice. The earlier same-work restart advantage is already corrected and tested; do not reopen that milestone or alter its frozen evidence.

Inspect a bounded set of **at most three opportunities reached from fresh default Camp**, using real paid prefixes and current player-visible actions. Nominate an opportunity only if source inspection identifies a concrete consequence: a later duration threshold, spare time while another person works, or a choice to finish versus stop useful work. Prefer ordinary early play and the existing supply window; do not manufacture extreme body/skill profiles or extend a search until a feature wins. Record every nomination and why any is rejected.

Before executing its comparison, bind the exact starting source/prefix, player objective, stopping time and serious controls. Compare finishing useful work, spending the same available interval on a useful alternative where feasible, and a deliberate partial-practice or delayed-completion route. For gathering, include **finish useful work, then forage** when feasible: current forage supplies the same gathering practice, yields food and has zero declared effort, so a needlessly costly control could falsely favor cancellation. A construction-learning consequence must concern a newly admitted job/stage, with workbench timing accounted for; same-stage stop/resume or earlier tool completion would repeat established mechanisms. Keep all actual time, food, effort, materials, ownership, other-person actions, installed work and remaining partial work in the record. An extra minute, a different worker or a forfeited output is a causal difference, not a nuisance to omit. If a diagnostic freezes practice, label that intervention explicitly and keep it outside ordinary player controls. Do not infer learning's effect from a changed end score alone.

Distinguish three outcomes: useful practice changes a later decision; deliberate training has a real cost and benefit; or withholding completion gains an advantage unmatched by the prespecified productive controls. Three nominations cannot rule out every competent alternative; a broader claim needs a source-derived bound. None is automatically a bug. A repair is warranted only for a demonstrated rule inconsistency or an unwanted incentive with an explicit design reason. A presentation improvement is warranted only where an exact current consequence is hard to see; keep the persistent HUD/tab layout compact and avoid exposing implementation parameters during play. Do not add a proficiency meter, learning faculty or new game merely to announce research progress.

Finish this preflight with the recorded opportunities, complete paid trajectories, independently checked source-specific conclusions and a concrete admission decision. If current controls suffice, close it without new mechanics. If a focused change earns its place, implement it, test the meaningful behavior, use an explicit version for incompatible contracts, commit/push/deploy and verify the public delivery. This new question is separate from the completed meal/offer studies and the completed empirical curve comparison; none needs another routine rerun.
