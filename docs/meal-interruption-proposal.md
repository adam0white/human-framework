# Next preflight: when interrupting a meal is useful

Selected after the completed private action-offer study, 2026-09-08; now closed as [the ordinary-meal preflight](meal-preflight-results.md), without candidate implementation. [The empirical learning-data pilot](learning-data-pilot-proposal.md) is next. This is an ordinary-use preflight. A meal-resume implementation depends on finding a useful existing interruption case.

## Current semantics and evidence gap

Camp's current meal reserves one shared portion, pays eight meal minutes and grants its single hunger relief only on completion. Canceling a partly paid meal keeps elapsed time, returns the portion and discards completion progress. Pausing the browser, a checkpoint or a reload already preserves the active meal. Releasing Meryem's project does not cancel her self-care. These are explicit authored semantics, not a demonstrated defect or a physiological model.

A default-created maintenance trace reaches a three-minute partial meal, then cancels and restarts it: [existing meal boundary](camp-current-comparison.md). That establishes ordinary reachability, but not a worthwhile reason to interrupt. Avoid repeating the action-offer mistake of building a candidate before checking its actual use.

## Gate before candidate code

Find one existing ordinary Camp decision where temporarily freeing the eater for another task serves a concrete current objective. Use only default creation and supported controls; preserve the complete paid prefix. Prefer an existing source-bound trace where possible. Do not alter a deadline, introduce a new scenario, or count a gratuitous cancellation as a benefit.

Compare serious current atomic controls:

1. Finish the remaining meal before the competing task.
2. Perform the competing task before starting the meal when that task was already available.
3. Cancel/restart when an actual intervening event makes that worthwhile.

Keep task availability, material arrival, ownership, body costs and the player's accessible information explicit. If a retained-progress alternative cannot improve a meaningful choice against those controls, close the direction without implementation. A shorter meal completion after unnecessary cancellation is insufficient.

## Conditional next step

Only after that gate passes, freeze the exact case, state ownership, interruption semantics and comparison before implementing one minimal alternative. It may retain one actor's reserved portion and already-paid meal progress while leaving the existing single completion relief intact. Distinguish a resumable pause from abandonment and specify what happens to the portion; do not grant unconsumed food or duplicate relief. Actual elapsed activity, other tasks, recovery, save/resume and actor consent remain explicit.

Do not introduce fractional nutrition, digestion curves, a general attention/physiology faculty, or a shared work abstraction by default. Keep the current atomic meal as the simpler control and frozen Human/runtime 0.1.1 untouched unless a concrete incompatible requirement earns a separately reviewed version. Ordinary usefulness and clear ownership are the admission criteria; no new levels or mechanism count is required.
