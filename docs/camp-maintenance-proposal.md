# Next milestone: a smaller maintained Camp consumer

Proposed after the completed [paid-work study](work-progress-results.md). This is the next executable maintenance task, not an implementation or release claim.

## Problem and intended result

The active Camp still depends on legacy Common Ground creation/imports, the older rain host, a story history-validation contract and multiple persistence layers. Those obligations served earlier continuation requirements. The user now permits retiring experiments and breaking old saves, and prioritizes the framework over a mandatory campaign.

Build one clean current Camp host around the released Human/runtime 0.1.1 and direct paid-work rules. Keep a deliberately small current snapshot contract. Old sources, save examples and negative studies stay private provenance; the new game need not execute every old format or authenticate absent historical commands.

This follows the paid-work decision without pretending that legacy machinery explains the independent helper's measured cost. That consumer already had no journal or migration.

## Work to retain before simplifying

First source-pin the current delivered Camp/Story/UI and choose a small set of executable synthetic traces covering:
- Fresh gathering and an independently accepted project.
- Automatic recovery, a meaningful readiness stop and an owned meal that pays before hunger relief.
- A tool improvement during work, stop/resume and accepted/refused handover with retained paid practice and materials.
- An earned supply window with competing actual kit uses, real dispatch versus missed deadline, then continued people/work/resources.
- A current-state save/reload at an active boundary, with reachable desktop/phone-width time and stop controls.

These preserve the useful work/agency interfaces and choices; they do not obligate new chapters, a longer quota or every earlier experiment. Retain any old result as an explicitly historical comparison when the new contract changes it.

## Bounded implementation

1. Measure current Camp's reachable source/dependencies, snapshot size, cold restoration and host validation obligations. Record synthetic workloads and exact source before editing; reuse completed evidence rather than rerunning old full matrices.
2. Define a new explicit host/save version using fresh setup and current people/world state. Remove transitive legacy creation/import dependencies and historical replay obligations from ordinary active saves. A minimal current-world transfer is optional only if cheap and useful; broad migration is not required.
3. Keep world ownership, consent, paid Human time/practice, retained physical progress and one-time output settlement in the host. Use the corrected direct reference rules where applicable. Do not package or publish the unpromoted helper merely as part of this cleanup.
4. Simplify persistence/UI around the chosen contract. Unsupported older files should fail clearly rather than silently fabricating history. General model limits remain collapsed; ordinary play explains goals, choices and consequences.
5. Compare the retained traces and measure actual dependency, state and restoration changes. Identify which removed guarantees account for lower cost. Inspect both an active and completed phase at mobile/desktop widths.
6. Review, run focused checks plus the required repository suite, commit/push, deploy and verify the exact live payload/source under the existing authorized workflow.

Stop when this smaller consumer is delivered and its changed contract is clear. Do not expand into an all-game rewrite, a generic campaign framework or new faculty. Any later scientific/theological or broader behavior claim needs its own evidence.
