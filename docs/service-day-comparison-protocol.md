# Service day: comparison protocol

Registered 2026-09-08 before this lane implements policies or executes service-day results. The new service host is being designed independently. This initial registration fixes the question, information boundary, analysis and evidence gates; a committed amendment must name its exact tasks, conditions and public view fields before policy implementation or any evaluation. Such an amendment is part of this protocol and must be included in the freeze. No host result is known to this lane at registration.

## Question and alternatives

Can a small host-native controller manage two people's successive service obligations using visible deadlines, owned resources and explicit paid recovery? The reference is an ordinary deadline/resource/recovery rule, not a work-only straw man. Add a second phase-aware rule only for a concrete hypothesis about an earlier resource or condition choice changing later feasible service. If no such distinction exists, retain one controller and diagnose the game instead of inventing a planning faculty. Neither controller imports laboratory Full.

Both policies receive only a detached public `getServiceView` projection. They cannot receive the host, export/import it for planning, invoke Human forecasts on hidden actual body, inspect another actor's private state, peek at future draws or clone a world to roll out alternatives. Visible task duration/cost/effort estimates and announced deadlines may be used for arithmetic. Host-owned requests, refusals, reservations, transfers, event priority and outcomes remain authoritative. Policies may request a partner action through the same player-facing command; they cannot suppress refusal or silently assign the partner.

## Fixed evidence standards

Development and reserved authored conditions run from identical validated input snapshots for every policy. Conditions must use legal host creation options or explicit paid command prefixes. Prefix body, practice, inventory, ownership and completed obligations carry into evaluation. Reserved conditions remain sealed until this protocol, the host and its transitive runtime/model/clock dependencies, policies and runner are committed and hashed in a separately committed freeze manifest. The CLI verifies those bytes against both the checked-out files and the freeze's source commit. A result command requires a fresh explicit output path and refuses overwrite before executing trials.

The same policy decision opportunities apply to all arms: after public command responses or visible event boundaries. Checkpoint observation must not add a policy turn. Each policy may explicitly recover for a declared number of paid minutes and then interrupt that rest, including short partial rests; the harness never provides recovery or resources as a fallback. Rejection is an outcome with public reason. At most eight zero-time commands may occur consecutively, and 2,000 total policy commands may occur per finite day. On policy/host exceptions or a bound violation, preserve the trace and partial result; do not discard or force success. The episode ends at the host's announced closing time. No seed search, coefficient tuning or deadline adjustment follows reserved execution.

Record each service independently: goal, route or method if available, delivery/completion minute, deadline, on-time/delivered status and unmet/partial quantity. Keep public partner responses separately, including actor, requested task, accepted/refused, time and reason. Record initial/final owned and reserved material and meals, actual consumption and transfers, paid work/rest/meal/idle minutes for each person, interruptions, pending jobs, command trace/counts, public views used for decisions, final save/hash, and exact resume parity. Do not emit a hidden weighted score or an aggregate 'Full wins' objective.

Demonstrate carryover using matched legal branches from the same starting save: change an earlier resource/work/recovery choice, retain all resulting costs and condition, and apply the same later requested sequence or same frozen continuation rule. Keep failure branches and pre-branch equality checks. These are bundled consequences of a prior decision; do not describe them as isolating a single physiological cause. A body-reset intervention would need a distinct explicit control and cannot be disguised as normal play.

## Complexity and analysis

Report every development and reserved case separately, pairing identical initial snapshots. Service timing is shown together with success/censoring, resource use, paid cost and remaining options. Reject claims of simple or complex policy dominance when one service improves at another service's expense. Authored deterministic cases are not a random sample, so no population significance or confidence interval is supplied.

Measure source bytes and nonblank lines for each policy plus all shared policy helpers, host/runner separately, and maximum serialized controller state/view/save sizes during execution. State budgets are 64 KiB for one finite host save, 32 KiB for one public view and 4 KiB for controller memory; all measured separately from the optional evidence trace. Exceeding a budget is reported, not repaired by omitting history. No CPU timing target is claimed in this lane. Code size is an implementation proxy, not measured human authoring effort, maintainability, cognitive realism or mobile performance.

This is a policy comparison under the same Human/runtime physics. It supplies no Human-versus-pooled-body evidence, empirical human validity, human enjoyment or five-person explanation result. The broader runtime, theology and scientific claims remain unchanged. Preserve old games, frozen probes and all negative findings. Keep these experiment modules and artifacts private; parent owns release and public integration.
