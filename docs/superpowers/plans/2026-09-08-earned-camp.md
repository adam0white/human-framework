# Earned camp implementation plan

> Use subagent-driven development with independent lifecycle, evidence and browser review. The existing autonomous authorization covers design, implementation, private commits/pushes and deployment; no further approval pause is needed.

**Goal:** deliver one continuing camp story whose people, supplies and unfinished work survive the transition into a ferry/rain supply window, with the tested ongoing-work correction and flexible recovery.

**Spec:** [earned-world proposal](../../story-continuity-proposal.md), [work contract](../../continuous-work-contract.md), [migration boundaries](../../continuous-work-migration.md), and the direct player feedback referenced by HANDOFF. Start from private main `2b3cbe5`; live app 0.10 is source `c51ae76`.

**Architecture:** a separately versioned full camp host in `src/games/camp.js` (host 0.2.0/save 2), a dedicated story wrapper in `src/games/camp-story.js` (host 0.1.0/save 1), and a progressively disclosed presentation at `/camp/`. Preserve all original ten games, old Common Ground/Rain and private experiments as controls. Both new hosts use frozen Human/runtime 0.1.1 and clock 0.1.0. No new package export or model coefficient.

## Parallel ownership and contracts

1. **Camp kernel (`codex/camp-kernel`).** Own `src/games/camp.js`, `docs/camp-kernel-contract.md`, `tests/camp-kernel*.test.js`, and kernel-specific artifacts. Begin by committing the exact public interface contract for the other lanes. Keep the established Common Ground names where practical: `createGame`, `startJob`, `cancelJob`, `requestProject`, `releaseProject`, `advanceGame`, `advanceToNextEvent`, `getGameView`, `exportGame`, `restoreGame`, plus explicit `migrateLegacyGame` and a recipient-consent handover request. A detached view should retain familiar clock, stock, structures, caches, people/current jobs, choices and last-response fields. Implement full gathering, durable assemblies, prospective workbench productivity, meals, flexible available-time recovery and an independent accepted-project policy. The root of a new save must validate the actual world and ownership without inventing missing pre-import history. Expose a declared default recovery mode and a separately testable simpler control. Strong bounds must retain unilateral stop/save/progression. Do not import private experiment code into a public module; derive and review needed code explicitly.
2. **Story wrapper (`codex/camp-story`).** Own `src/games/camp-story.js`, `docs/camp-story-contract.md`, `tests/camp-story*.test.js`, and wrapper artifacts. Consume the kernel contract; coordinate source commits without editing the kernel lane. Expose create/migrate, action forwarding, advance/next-event, get-view/export/restore, supply allocation, ferry dispatch, and chapter/ending continuation. Detect the first actual camp milestone after tied events and preserve the entire underlying selected-kernel state. One saved supply-window record owns entry, relative deadlines, carried caches, subsequent production and allocations. A checkpoint/Continue operation never supplies food or changes paid body/work. Legacy established imports enter at current time and retain old caches without made-up birth timestamps. Keep ordinary deterministic save continuation separate from claims of complete historical replay.
3. **Evidence (`codex/camp-evidence`).** Own an early registered protocol, private source-bound runner/policies under `src/experiments/camp-story`, tests and evidence documentation. Preserve old synthetic and actual supplied-state controls privately. Compare at least sensible build-first/stock-first choices, snapshot/prospective productivity independently of recovery where supported, earned versus authored entry, mixed busy imports and a late-ferry continuation. Register small withheld boundary cases before final source freeze; do not tune after seeing them. Report paid time, material/food/effort/practice and source/size bounds separately from service outcomes. Exact-root branch commits and first failures stay available. No player exports or original feedback go to external reviewers.
4. **Root presentation and delivery.** Own `web/camp.html/js/css` and session adapter, routing/collection integration, app version, consolidated review/handoff and release evidence. Use the existing compact HUD/tab vocabulary, finite Next Event, clear distinction between simulation Pause and actual Stop, visible own/neighbor consequences and explicit handover consent. Surface useful choices gradually without locking valid alternatives. A new story has its own save/slot; chapter restart is absent from the main flow, while deliberate new-story/replay access preserves the current save. Reuse actual scenario logic, not a linked playlist or normalized body/stock at chapter boundaries.

## Admission and migration requirements

- Support complete mixed states: active assembly, gathering, meal, rest, idle, accepted project, pending events and previously earned caches. Preserve active fixed-output gathering/meal contracts; do not gift output or meals. Declare any conversion/preemption of inherited rest explicitly, retaining all paid recovery.
- A workbench changes only prospective productivity. Retain already-paid fraction, effort and skill exposure. Same-worker stop/resume cannot refresh a bonus or outrun uninterrupted work; a consenting replacement uses their own condition/skill and pays only future effort.
- Automatic low-demand recovery applies only when unassigned; it never feeds anyone. The neighbor can pursue accepted work and choose recovery/food through a disclosed authored policy. Next Event has a useful finite boundary even if nobody has a job. Action availability must agree with actual admission or state an explicit uncertainty; preserve the old rounded-capacity counterexample.
- Preserve the stock-first camp milestone with live gathering/rest, the old 1,312-minute state with twelve caches, and late local failure with subsequent camp provision. Do not force a quiet transition, confiscate surplus, manufacture missing receipts or claim the new importer is complete from idle-only fixtures.
- Controls and science: old hosts/replay locks and Solo Repair stay unchanged. New tests establish software behavior, not five human participants, physiological calibration, physical-device timing or theological validation.
