# MVP evidence lanes while the continuing worksite is playtested

Date: 2026-09-07. Starting source: `9bd93c6`. Authorized by the user's request to keep progressing in parallel while they play Common Ground.

## Design and stopping rule

Advance the reusable kit by testing its boundaries and its value. Keep the live 0.5 games and their simulation versions stable during this work. The three lanes are independent, privately reviewable experiments; none needs a new public game or a new cognition variable. A candidate that does not earn its complexity stays experimental or is rejected with its evidence retained.

1. **Cooperation candidate:** a bounded, addressed proposal/response/commitment record, tried in resource exchange and ongoing work. Compare direct host rules. Keep world effects, feasibility, observations and meaning in the hosts. Do not add it to the runtime package yet.
2. **Competent simpler controller:** compare a small Common Ground controller with the current authored controllers, using the same public observations and unchanged world physics. Freeze conditions before running, retain partial and negative outcomes, and distinguish policy comparison from mechanism comparison.
3. **Independent packaged consumer:** author a small headless maintenance/watch host using the installed package's public API. Exercise concurrent and interrupted jobs, one approaching event, coherent save/resume, resource ownership, solo operation and alternate time drivers. Record integration friction rather than claim blind onboarding by a reviewer who already knows this project.

Root owns integration, primary-source grounding, stale decision-status corrections and the evidence report. Each author works in a separate branch and owns new files. Shared runtime fixes require a reproduced failure and explicit version/compatibility handling; do not silently alter live physics.

## Verification and review

- Write focused behavioral tests for new contracts; use observed failures to drive implementation.
- Independently inspect each committed diff and run its tests after integration.
- Cross-review the cooperation and consumer lifecycle, and the comparator's information access and evaluation claims.
- Run the full existing suite once all scoped changes are integrated. Check public build bytes remain unchanged if only private experiments/docs were added.
- Preserve published benchmarks and supplied snapshots. Do not use simulated people or AI reviewers to mark the formative human playtest complete.
- Commit and push verified private-source progress. Deployment is needed only if public payload changes; keeping the live release stable is intentional for the user's current session.

## Reviewable result

Executable experiments, reproducible artifacts, a short source-grounded social-design memo, and an updated MVP gate table saying what passed and what remains open. No automatic promotion of social cognition, empirical realism or a universal framework claim.
