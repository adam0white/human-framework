# Calendar index experiment — 2026-11-03

Remaining: Child's original performance, restore, replay and milestone gates remain open. The time/phase queue index was rejected for release because this measurement showed no consistent material benefit. No engine change was committed or published.

## Method and result

A private generic control used the existing numerical fixture with one person and 5,500 civil-day calendar entries. It exercised a first day, an accepted sleep request, a scheduled review and a public interrupt request. It did not establish ordinary work or interrupted settlement. A pending interrupt shortened the intended later interval. This is a small functional case, not Child's six-person 36/180-month workload.

The untouched source baseline at `1d6e3fce7cb4bc0b71a5b79a85ef28913428e5f5` supplied current-state, history, initial-premises and complete returned-result fingerprints. The candidate indexed queue times and phases within one operation, preserving the complete visible queue and occurrence order. Node 26.12.0 focused verification passed three files and seven tests, including strict JSON restore, replay and same-next continuation. An earlier Node 23 pass was excluded; earlier private fixture and loader failures were retained separately.

The cost comparison loaded the verified published HF 4.16.2 package and the unbuilt source candidate in one Vite SSR process. All 197 extracted reference-package files matched the published archive. Each arm received a fresh run and person, one warmup and three measured pairs in alternating order. Only synchronous public `step` calls were timed. Loading, exports, cloning, hashing, comparisons and file writes were outside the intervals.

## Daily clock correction

The original failed Child qualification already used daily fidelity. Its candidate `src/hf.ts` has SHA256 `604e4cf7a1effd56a53d5f19be3a64fea642ca8f59c4d4c762c9cb13b50b011a`: `serve`, conditional stepping and preview pass `{mode:'daily',dayMs:86400000,anchor:0}`. Switching that qualifier to daily is therefore not a new experiment or a performance fix.

The current framework selects one fidelity per batch. It has no separate foreground/offscreen selector within a shared run. A per-person policy needs an upstream contract for shared causal timing. Daily changes the numerical approximation; retaining faculties does not prove identical fine/daily outcomes. The original 1,045,165.849 ms Child result against 2,000 ms remains failed. It is not a fine-clock measurement.

An existing-archive allocation census found 64 entries in the exported current journal. That journal is a retained tail, not the live lifetime allocation index. Memory identity counters also do not alone count allocations. Accepted history stores inputs and scheduling metadata, not the missing allocation outcomes; exact lifetime receipts require replay. No lifetime-growth or dominant-cost conclusion follows from those numbers.

## Reference iterator experiment — 2026-11-03

A second private candidate changed only the internal joined-reference iterator and added three characterization tests. It preserved live values, duplicate/alias order, sticky exhaustion and error cursor behavior; private iterator identity and branding deliberately differed. Three baseline tests passed on unchanged production. The candidate passed scoped typechecking and four focused files/16 tests under Node 26, including the public 48-hour replay and archive recovery. All 9,054 source files matched before and after that focused run. The first baseline snapshot setup failed before capture; later verification established unchanged tracked source and the ten known file pins. It is not a full-before snapshot claim.

A synthetic validation benchmark used the same published memory validator for both views. Seven alternating pairs of 20 validations per case preserved complete ordered issues and input state. With 1,361 references and 200 retained episodes, median batches were 5.666 ms published versus 2.808 ms candidate, about twice as fast. The 45-reference case improved less; the empty-reference case was slower. These are component timings, not whole-game timings or proof of lifetime allocation growth.

A separate paired public call used the exact one-person 48-hour fine fixture, with no inputs, through fresh runs in each implementation. One warmup per arm preceded seven alternating pairs. Only synchronous step calls were timed. Median native time was 268.065 ms published versus 268.377 ms candidate; the candidate was faster in three pairs. Complete initial archives, returned results and final archives matched within every pair, with matching current/history/premises/result fingerprints. This paired run did not replay; the separate focused 48-hour test did. The unbuilt candidate retained the old generated engine identity solely for this private comparison; no archives were retagged and no package was published.

Both diagnostic parents and runners returned zero. Root verified the recorded process gone, all 9,054 source files and 197 published reference files unchanged. For the whole-call run, all 11,053 dependency entries and 32 input pins also matched. The parent measured 7.349 seconds; the observed physical-return upper bound was below 180 seconds. JavaScript versus TypeScript loading, JIT, GC, OS variation and one generic fixture limit inference.

**Decision: no release on this evidence.** Faster synthetic validation did not produce a useful gain in the measured public call. The patch and tests were preserved privately, then removed from source. This does not establish that the iterator cannot help a different, longer-lived workload. A representative Child measurement remains missing, with a games-deferred recheck on 2026-11-10. The original Child budget, restore/replay and milestone gates remain open.
