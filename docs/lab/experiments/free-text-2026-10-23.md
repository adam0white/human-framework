# Free-text suggestions, 2026-10-23

The host prototype is in **Voice**, behind the Game menu's **Experimental free-text suggestions** toggle. It starts off on every page load. The player writes a request, Clef ranks the currently listed acts, Clairic copies explicitly named actors and times, and the page offers one exact suggestion for confirmation. It always shows Halil, now, mention, no insistence, and his ability to refuse. It does not send an act until the player clicks Confirm. The ordinary controls stay available.

This changes host input only. It adds no HF faculty, package version, future orders, conversation grammar or obedience. Text and listed labels go to Cloudflare; no Person, hidden score or spiritual state does. Input is capped at 400 characters. The notice asks players to avoid personal details. The Worker does not retain request text or model output. The existing run records only the confirmed canonical suggestion through the ordinary input path. Replay makes no translation calls.

The menu reference is the hand-labelled choice or deliberate no selection. It is an attainable reference, **not a human UI study**. Correction effort is a proxy: one dismissal for a false candidate, one menu selection for a missed request, two actions for a wrong supported act. Typing, reading, confirmation time and actual human corrections were not measured. This trial establishes no usability benefit.

For supported outputs, target is Halil and timing is now, so the first accuracy column checks the complete supported triple. Unsupported targets or times require abstention. Clairic's literal actor extraction matched 39/40 labels; it misread Selin as the actor in “Give Selin a call.” Literal time spans matched 33/40: it missed six explicit time phrases, including “tomorrow” and “İftardan sonra”; it extracted “4pm” rather than the labelled “at 4pm.” That last difference is a span-boundary mismatch, not a lost time.

**The models did not enforce the boundary reliably.** Both stages accepted “Halil, rest tomorrow” and “İftardan sonra dinlen” as immediate rest. Several JSON/system instruction strings also became suggestions. Extraction removed the two wrong-actor candidates and the 4pm request but did not make the parser reliable. Qwen's JSON arrived in `choices[0].message.reasoning`; the first runner's `response`-only parse treated every answer as absent. The scorer and final runner handle this known endpoint format. No extra inference calls were made to repair parsing. `raw.json` retains the original runner predictions; `scored.json` contains the corrected parse.

The host now conservatively rejects explicit future phrases and model-instruction forms before accepting a candidate. These exclusions were added **after seeing this sample**. Its 40/40 is a regression check on the development sample, not independent evidence of general accuracy. Unseen phrasing can still be misunderstood. Confirmation remains necessary. The 0.65 threshold was chosen before the run but has not been calibrated.

## Runtime limits and fallback

There was no existing AI binding in the site configuration. This change adds that binding to the existing lab Worker and a fixed-model `POST /lab/api/translate` route. It accepts only the site's origin, bounded text and listed labels. It cannot execute any act. It does not accept a caller-selected model or arbitrary prompt schema.

One conditional R2 counter reserves **$0.04 per pair before either call**, permanently, including failures and browser timeouts. Its 25-call lifetime cap allocates $1; ten calls per UTC day allocate at most $0.40/day. The browser also reserves ten tries/day in localStorage, and the same atomic object enforces ten/day for each random browser ID. Browser IDs can be replaced; the lifetime and daily global caps still hold. The counter stores only counts, the current UTC day and random browser IDs. It must never be deleted to recover capacity. A provider failure circuit-breaks future admissions pending manual review. The local benchmark and Worker have disjoint allocations.

The reservation exceeds full-context input cost for one Clef question and two Clairic field passes: 65,536 × ($0.24 + 2 × $0.10) / million = $0.028836. Both models charge input only. Source: [Clef model](https://developers.cloudflare.com/workers-ai/models/clef/), [Clairic model](https://developers.cloudflare.com/workers-ai/models/clairic/), checked 2026-10-23. R2 compare-and-swap follows [conditional operations](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/#conditional-operations). No automatic retries or refunds occur. Price/model changes require rechecking this bound.

The input focuses ordinary game pause. One request is allowed at a time. A five-second browser deadline falls back to the menu; in-flight provider work may finish and remains reserved. Changed run, day, minute or act list invalidates the proposal. Before confirmation the page checks the current listed identity again; the existing host suggestion path validates availability. Model absence, malformed replies, invalid spans, low confidence, cap exhaustion and inference errors all leave the menu usable.

Nine focused tests cover listed-act validation, forged/missing extraction, explicit unsupported text, stale scenes, confirmation, atomic caps, disabled inference and the provider-error circuit breaker. Typecheck passes. The coordinator runs the complete suite, independent review and delivery checks. No browser playtest or deployment has been claimed here.

**Decision:** keep this as a default-off prototype. Do not present the model output as an accurate understanding of player intent. The benchmark supports keeping an explicit confirmation and deterministic menu fallback; it does not establish that free text improves play.
