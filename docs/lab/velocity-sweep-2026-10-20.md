# Lab velocity sweep (2026-10-20)

The owner asked for a sweep of the repo's fences and rules: what slows the lab down, and what to keep. Owner, 2026-10-20: "I don't want to become a slow enterprise, but always an R&D lab with cool futuristic ideas."

Short answer: hosted CI is not the slowdown. It takes about 3 minutes on clean runners and is already cached, sharded and cancel-on-supersede. Most of the measured time goes to **the full local `npm run check` on one machine that ten-plus agents share**, and to **agents colliding in one shared checkout**. The fix is lanes by touched paths (strictest wins), one full local suite at a time, deploy trusting CI for the exact commit, and one worktree per agent. Model-run work (reviews, playtests, ledger triage) costs as much per item as a loaded check, but it carries the lab's taste signal; this sweep does not cut it, it only stops it waiting on checks.

Patterns: (1) four different Playwright install commands; the tests need `chromium-headless-shell`, and the mismatch caused 5 of the 11 non-Neighbours failures. (2) UI tests are environment-fragile (hard-coded paths, Linux font geometry, fixed 10 s hook timeouts under load). (3) Repos raise `--testTimeout` instead of separating slow work. (4) `deploy` in every game repo is `npm run check && npm run build && wrangler deploy`, so each deploy repeats the full local suite. (5) Neighbours runs its whole evidence pipeline (e2e, 30-day stress, replays, audits) on every push: ~14 min and 45 % red.

Recommendations for game repos, for their owners: one Playwright step (`npx playwright install --with-deps chromium-headless-shell`); the same lane split and suite lock as HF (the lock is machine-wide, so game checks should take it too); `deploy` checks the commit's CI instead of re-running `check`. Neighbours, if unfrozen: move the expensive evidence off ordinary pushes, but keep it as the release gate for the exact SHA being published, with its source-digest checks. Rope, Small Works and Neighbours are frozen (652cfac), so nothing is applied there. Game repos other agents are editing were not touched.

## R&D lab operating model

Lanes by touched paths, strictest wins (from the frontier scan, [frontier-2026-10-20.md](frontier-2026-10-20.md) §3, revised after a Codex contrarian review). `npm run check:lane` classifies the files changed against `origin/main` (committed, staged, unstaged and untracked) and runs the lane's checks. A path no rule names is gated, so a new config file cannot slip through as fast.

| Lane           | Paths (the strictest file decides)                                                                                                                                                                                                                                                                                                                                                                                                                                                             | Before commit                                                 | Before it is public                                                                                           |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| **Gated**      | `packages/human/**`, `packages/lab-client/**`, `packages/lab-kit/**`; the lab Worker and everything it imports (`apps/site/worker/**`, `apps/site/src/lab/**`); every `package.json`, `package-lock.json`, `.nvmrc`, `tsconfig*.json`, `biome.json`, `vitest*.config.ts`, `wrangler.jsonc`, `apps/site/public/_headers`; `.github/**`; `scripts/deploy.ts`, `scripts/release.ts`, `scripts/suite-lock.ts`, `scripts/lane.ts`, `scripts/*.sh`; `AGENTS.md`, `CLAUDE.md`; any path no rule names | Full `npm run check` (under the suite lock)                   | HF releases: independent review, headless control, exact legacy continuation, CI green (owner-set, unchanged) |
| **Delivery**   | What the browser loads outside game logic: `apps/site/public/**`, `apps/site/**/*.html`, `apps/site/vite.config.ts`, service workers, release stamping                                                                                                                                                                                                                                                                                                                                         | Lint, typecheck, related tests, `npm run build`               | CI green on the exact commit                                                                                  |
| **Fast**       | Game and site code: `apps/site/src/**` (except `src/lab/**`), `packages/playtester/**`, other `scripts/*.ts`; the ledger inputs `docs/lab/feedback-ledger.md`, `lessons.md`, `testing-asks.md` (they are read at runtime, so the lane names their test, `apps/site/src/lab/lab.test.ts`, explicitly instead of relying on the import graph)                                                                                                                                                    | Lint, typecheck, tests related to the change                  | CI green on the exact commit                                                                                  |
| **Experiment** | A branch or `~/code/.lab-scratch` worktree with no deploy and no release                                                                                                                                                                                                                                                                                                                                                                                                                       | It builds and runs, plus one written, falsifiable observation | Promoted into another lane, with that lane's checks                                                           |
| **Prose**      | `docs/**`, `research/**`, `archive/**`, other `**/*.md`, `LICENSE`                                                                                                                                                                                                                                                                                                                                                                                                                             | Lint                                                          | CI runs on push                                                                                               |

Always: CI runs the full suite on every push to `main`; deploy requires `ci` green on the exact commit and builds from a clean checkout of it; one full local suite at a time on the lab machine (`npm test` waits for a machine-wide lock; `SUITE_LOCK=0` and CI bypass it).

**Measure for a week (2026-10-20 to 2026-10-27).** Record, per lane commit, time from "change ready" to "usable revision on `main`" (local checks, lock wait, CI, cancellations, repair) and every defect that reached a live site. Baseline: this doc's numbers. Keep the lanes if time falls and escaped defects do not rise. If more than about one push in ten turns `main` red, the fast lane is too fast.

**Worktree per agent.**
- `npm run wt -- add <repo-dir> <name>` creates `~/code/.lab-scratch/wt/<repo>/<name>` on a new branch from `origin/main`. Worktrees live outside every repo, so a nested `biome.json` is never scanned. `npm run wt -- rm <repo-dir> <name>` removes it.
- Integrate from the worktree: `git pull --rebase origin main`, then `git push origin HEAD:main`. Deploy with `npm run deploy`: it checks CI for the commit and builds from its own clean checkout, so it does not need the shared checkout to be clean.
- Extracts of other repos (playtest builds, source snapshots) go to `~/code/.lab-scratch/`, never into a repo's `scratch/`.

**How CI failures route.**
1. The pusher owns a red run on their own commit. A coordinator sees all of them with `gh run list --status failure`.
2. Fix forward with a new commit, or revert if the fix is not obvious. Never re-run a red run without a cause.
3. While `main` is red, keep working in your worktree, but do not push further unverified commits on top of it: stacked failures and cancelled runs hide who broke what.
4. A timeout that passes alone is a finding about contention, not proof the test is fine: record it in docs/findings.md and look at load and the suite lock before raising a budget. Semantic assertions stay in the suite; only wall-clock budgets belong in the bench.

## How this was measured

- Local timings: `/usr/bin/time -p` on lint, typecheck and `vitest run --reporter=json` in the shared checkout, 2026-10-20 13:31–13:45, load average 77–135 on 10 cores; the Codex worker's own timings (scratch/velocity-hf-worker.md) with load recorded per run. Earlier runs from `scratch/checks/*.log` are Vitest durations with load not recorded.
- CI: `gh run list` and per-step durations from `gh run view --json jobs`; failure causes from `--log-failed`.
- Not measured: agent-time lost to collisions (incidents counted only), review and playtest wall time per change, and hosted CI time after the shard change until the first runs land.
- Reviewed by Codex as a contrarian (2026-10-20). Accepted: CI trust fails closed and builds from a clean checkout of the exact commit; gate the lab Worker's imports and default unknown paths to gated; name runtime-read ledger inputs explicitly; correct the timing comparison and the "false timeouts" claim; report CI-only outcomes and cancellations; count model-run work; keep review diversity sized to the change; do not stack commits on a red `main`; keep semantic tests out of the bench; keep Neighbours' evidence as the release gate. Not taken: none rejected outright; build-time curation is deferred, not dropped.
