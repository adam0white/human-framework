## Source and cloud execution

Use `.node-version` and `packageManager` from the selected commit, currently Node 26.12.0 and pnpm 12.16.1. Run `pnpm install --frozen-lockfile`, then `pnpm check`. HF and Games need no sibling checkout for their supported build and CI. CI already runs Linux with the pinned tools. Never copy `node_modules` to replace a frozen install. For browser jobs, run `pnpm exec playwright install --with-deps chromium` on the Linux runner. Keep game and HF commit IDs in every qualification receipt.

Use one worktree per worker. The Mac `npm run wt` helper is optional in cloud sessions: use `git worktree add -b <task> <session-directory>/<task> origin/main` and frozen-install there. Remove only that worker's clean, merged worktree. HF's suite lock currently defaults to `$HOME/code/.lab-scratch/locks/full-suite`; its CLI has no directory override. Cloud CI uses its existing CI bypass. A future interactive cloud runner must add a configurable common lock directory, with all workers sharing it; do not pretend `HF_SUITE_LOCK_DIR` configures HF today. Games supports that variable. Keep signing enabled and provision a GitHub-accepted signing identity through the cloud environment's private credential facility. Verify a test commit's signature before pushing a task. Never commit key files or weaken signature rules.

## Daily WAI replacement remains proposed

The current `work.adamwhite.lab-wai-play` LaunchAgent uses the Mac HF checkout and `wai-daily` scratch state. Preserve that checkout, plist and state until the replacement has qualified and the owner accepts retirement. A Cloudflare cron alone cannot run this Node/Playwright process. Proposed replacement: one serialized Linux runner with a private persistent volume, or Actions with private durable conditional-write state. Public Actions artifacts are not private state storage.

Implement these changes before enabling the replacement:

1. Add one configured state directory shared by `lab-wai-play.ts`, `lab-wai-budget.ts` and the installer. Replace Homebrew child executables with `process.execPath`. Check free space on the state filesystem.
2. Preserve the complete current budget, reservations, scheduled-day markers, locks/admission state and reports privately. Verify hashes after transfer. Do not initialize a fresh ledger or reclaim uncertain spend. Use conditional writes or a single durable writer; Actions concurrency alone does not make ephemeral state durable.
3. Add a monorepo source root to `lab-wai-reading.ts`. Current `sourceRepo()` still searches separate repositories. Map `repair` to `games/smallworks` and Neighbours native code to `games/neighbours/neighbours`. Voice, Well and Watch stay in HF. Point adapters at `PASS_DIR`, `WARREN_DIR`, `GLANCE_DIR`, `MURMUR_DIR`, `SMALLWORKS_DIR` and the documented Neighbours source. Qualify imports and current editions; directory mapping alone is not proof.
4. Run at 16:00 America/Chicago. If using UTC Actions cron, schedule both 21:00 and 22:00 UTC, then enforce the local-time and once-per-day gates. Confirm DST behavior. A cron can be delayed; record actual start and admission result.
5. Verify one bounded run, its comparison/control, retained reports, budget before/after, and no second spend on a duplicate invocation. Retain failures. Then ask the owner to accept the cutover. Only afterward boot out the exact LaunchAgent and remove its plist.

The owner step is secret entry plus acceptance after those receipts. The engineering changes above remain work; they have not been shipped by this cleanup.
