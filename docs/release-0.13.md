# App 0.13 — a smaller maintained Camp

Delivered 2026-09-08 at [The camp](https://human.adamwhite.work/camp/).

## Delivered behavior

The active Camp now uses a fresh direct Camp 0.3.0 host and one current snapshot. Automatic available recovery, owned eight-minute meals, retained partial construction, prospective workbench improvements, accepted handover and the earned supply-window consequences remain. Compact tabs, condition/job HUD and explicit time/stop controls remain available at the tested phone and desktop sizes. Restored or imported checkpoints show their actual next choice, and the returned camp explains that further caches stay stored after allocations settle.

The new save key `human-camp-current-v0.3.0` stores one current camp. Current downloads support preview, explicit replacement and resumption; a secondary new-camp action replaces that current save. Older formats are unsupported and old story keys are never read or overwritten. Quota, unreadable-storage and asynchronous-import protections retain playable state and actionable download paths. The user explicitly authorized save breaks and disposal of obsolete experiments.

The active host no longer imports historical Camp/Story, Common Ground/rain hosts, Human 0.1.0 or private work candidates. Five old Camp host/browser/session/slot modules leave public and local serving; their exact sources remain private historical evidence. Laboratory retirement stays in effect. Human/runtime 0.1.1, clock 0.1.0, shared model and historical host sources are unchanged. [Current host contract](camp-current-contract.md) · [Interface and persistence](camp-current-interface.md).

## Measured maintenance result

The source-pinned baseline contains six fresh traces and 201 original commands, covering gathering, readiness/meals, accepted partial work/handover, ongoing tool improvement, fulfilled and unmet supply windows, and return. Every retained physical value matches after every command, including unrounded people/work/resource state. Nine intentional view changes remove hypothetical Next forecasts while a supply checkpoint already prevents advancement. This is selected-trace equivalence, not exhaustive behavior or human validation.

Active Camp JavaScript falls from **13 files / 165,781 bytes to 7 / 98,953 bytes (40.3% smaller)**. Core closure falls from **10 / 129,652 to 5 / 72,956 (43.7% smaller)**. Successful-return snapshot falls from 11,525 to 6,509 bytes; its five-process local cold parse/restore median falls from 53.69 to 2.31 ms. The tool-completion snapshot grows **19 bytes**, and its pre-tool snapshot grows **113 bytes**. These are raw source and local synthetic save measurements, not compressed transfer or browser-performance results.

Savings deliberately remove old origin snapshots, command history, migrations, research setup and five-slot validation. The new snapshot checks retained current consistency; it does not authenticate arbitrary missing history. A bounded body edit after dispatch is admitted where the old window journal rejects it; both already admit the same edit after Return. The smaller implementation therefore has a weaker historical contract.
