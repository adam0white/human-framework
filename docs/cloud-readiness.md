This is an audit and a set of proposed changes, not a record of a cloud cutover. Human Framework's CI runs on Linux, but several interactive and scheduled workflows still assume the owner's Mac. Preserve the existing Lab Worker, R2 data, identity service, curated records, Watch, Voice, Well and Island routes while changing operations. Do not stop the Mac scheduler or remove its state until replacement receipts are verified and the owner accepts the cutover.

On 2026-11-12, the coordinator observed that the separate local game source directories were absent. The current reader maps Neighbours to a separate Concordia checkout, Repair to a separate repair-game checkout, and other external games to separate directories; Voice, Well and Watch use the HF root. The Pass, Warren, Glance, Murmur and Small Works adapters have environment overrides but default to separate checkouts, while the Neighbours example requires `NEIGHBOURS_DIR`. A cloud replacement should select an immutable Games monorepo revision, map Repair to `games/smallworks` and the Neighbours native source to `games/neighbours/neighbours`, and verify editions and dependency resolution before use. This observation does not establish a scheduler run or cloud cutover.

The WAI budget free-space check currently calls `statfsSync(homedir())`; when state moves, check the filesystem that actually holds that state. The Playwright npm-cache searches are optional fallbacks, not required source paths. Historical curated source links remain provenance, not runtime dependencies or proof of transfer. No scheduler was probed, stopped or migrated in this follow-up.

Its plist schedules 16:00 local time, runs `/opt/homebrew/bin/node` against `/Users/abdul/code/human-framework/scripts/lab-wai-play.ts` from that checkout, and writes to `/Users/abdul/code/.lab-scratch/wai-daily/launchd.log`. Retain the Mac checkout and scheduler state until a replacement has verified receipts and owner acceptance.

The existing local daily scheduler uses persistent budget and admission state. A proposed Actions replacement needs serialized execution, durable state, DST-aware scheduling and verified receipts; it has not been implemented. Recreating state on every run could reset its accounting. Human Framework's central production deployment currently uses the guarded CLI in `scripts/deploy.ts`, not a verified cloud deployment workflow. It builds in a temporary Git worktree, requires current main and successful CI, and needs authenticated GitHub access and privately supplied Cloudflare authorization. Verify a replacement's source, environment, bindings and live release before treating it as operational. Do not put credentials in source or logs.

Cloud signing must satisfy repository policy without depending on Mac key paths. Historical local links in curated research records are provenance, not proof that their files have been transferred. Preserve the originals and verify any replacement archive. These proposals do not migrate central telemetry, R2 data, identity, budget state or the scheduler.
