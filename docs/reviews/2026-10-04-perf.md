# Performance review, 2026-10-04

Adversarial, read-only. Repo HEAD `ab4d270`. The live site serves `abde83c` (`/release.json`). Bundle numbers below say which build they come from. Scratch scripts are in the session scratchpad (`perf/timing.ts`, `perf/site/frames.perf.ts`). They are not committed.

**Scope:** framework timings come from Node 26 on Apple Silicon. Game worker timings come from a headless harness running the real `VoiceGame` and colony `Playback`. The browser main thread was **not** profiled. Main-thread findings are from reading the code.

## Top line

1. The live site ships every asset uncompressed and tells browsers to revalidate "immutable" assets. One inherited header line causes both.
2. Fonts (~254 KB of woff2, render-blocking) are the second-largest payload.
3. The framework scales linearly to 200 people at ~0.05 ms per decision. Its own wall-clock budgets fail on this machine.
4. Nothing persists, so save size matters only to framework hosts. Persons are bounded at ~330 KB each.

## VERIFIED

### Site delivery

**V1. HIGH, effort S. `no-transform` disables all compression on the live site.**
- Source: `apps/site/public/_headers:5` sets `Cache-Control: no-cache, no-transform` on `/*`.
- Cloudflare docs: "Compression is disabled when the `no-transform` directive is present" (developers.cloudflare.com/cache/concepts/cache-control).
- Measured with `curl -H 'Accept-Encoding: br, gzip'` against human.adamwhite.work: no `content-encoding` header on any HTML, JS or CSS response.
  - `jsx-runtime-DYo_nt5P.js` downloads at 219,523 B. Brotli would be 58,267 B.
  - Voice worker `worker-B8f5C4u7.js` is 248,043 B. Brotli would be ~70 KB.
- First-load JS+CSS, raw vs brotli (HEAD build):
  - `/voice/`: ~568 KB raw vs ~154 KB brotli.
  - `/colony/`: ~586 KB raw vs ~159 KB brotli, plus the 242 KB hindsight worker at the end screen.
  - `/`: ~242 KB raw vs ~64 KB brotli.
- Fix: delete `no-transform` from line 5. No current asset needs it.

**V2. MED, effort S. Hashed assets get `no-cache` merged into their immutable policy.**
- Live header on every `/assets/*` file: `cache-control: no-cache, no-transform, public, max-age=31536000, immutable`. Cloudflare merges the `/*` rule and the `/assets/*` rule (`_headers:5,8`), and `no-cache` wins.
- Effect: each repeat visit costs one conditional request per asset. I measured a 304 with ETag, so it is a round trip each time, not a full download.
- Fix: put `! Cache-Control` above `_headers:8` to detach the inherited header, then set `public, max-age=31536000, immutable`. Keep `no-cache` for HTML only.

**V3. MED, effort M. Google Fonts: render-blocking cross-origin CSS and ~254 KB of latin woff2.**
- Every `index.html` links `fonts.googleapis.com/css2?...`. The voice page loads four families: Fraunces (variable, opsz + wght axes, upright and italic), Instrument Sans, JetBrains Mono and Spectral. The CSS has 35 `@font-face` rules.
- Measured latin subset: Fraunces 82 + 67 KB, Instrument Sans 30 KB, JetBrains Mono 31 KB, Spectral 3 × ~15 KB. That is 254 KB, more than all the app JS after brotli.
- Fix: self-host woff2 under `/assets/` so it gets the immutable cache and no third-party round trip.
  - Drop the `opsz` axis, or pin Fraunces to the few weights in use.
  - Drop Spectral or JetBrains Mono if they are used only for small text.
  - Add `<link rel=preload>` for the one face used above the fold.
  - CSP `font-src` can then become `'self'` only.

**V4. LOW, effort S. React (219 KB raw / 68 KB gz) loads on the landing page.** `/` is a 12 KB entry (`src/home/main.tsx`) that pulls the shared `jsx-runtime` chunk (react-dom).
- Fix: once V1 is fixed this costs ~58 KB brotli and is cached for the games. Acceptable. Prerendering the home page to static HTML is optional.

**V5. LOW, effort M. The framework is bundled three times, once per worker.**
- `worker` (colony) is 245 KB, `hindsight-worker` 242 KB and the voice `worker` 262 KB, all raw (HEAD build). Each is an IIFE with the full framework inlined. The main-thread chunks contain no framework code, which is good.
- The hindsight worker (`colony/ui/EndScreen.tsx:41`) re-downloads ~240 KB at the end screen.
- Fix: serve the hindsight job from the existing colony worker as a message type, or build the workers as ES module workers (`worker.format: 'es'`) so they share a chunk.

**V6. LOW, effort S. The worker download is serialized behind the entry JS.** The worker URL is only discovered when `useColony.ts:122` or `voice/ui/transport.ts:7` executes, so the first frame waits for HTML, then JS, then the worker.
- Fix: add `<link rel="prefetch">` for the worker chunk in the HTML. This needs a small Vite plugin, or a hand-written link to the hashed name via the manifest.

### Framework

**V7. INFO. Throughput is linear in population.** Measured with `perf/timing.ts`, village scenario, warm JIT, `maxEvents` unbounded:

| people | ms per sim-day | ms per person-day | ms per decision |
|---|---|---|---|
| 1 | 2.6 | 2.60 | 0.074 |
| 10 | 23.9 | 2.39 | 0.067 |
| 50 | 81–103 | 1.6–2.1 | 0.05–0.06 |
| 100 | 151 | 1.51 | 0.048 |
| 200 | 296 | 1.48 | 0.047 |

- A 200-day run with 10 people steadies at ~30 ms per sim-day from day 20 on, with no drift (600 → 559 ms per 20 days).
- Heap moved 20 → 174 → 98 MB. That is a GC sawtooth, not a leak.
- The CPU profile is flat. `consider` is 27% inclusive and 10% self (`cognition/cognition.ts:278`). `tick`/`advanceSegment` is 17%, `finish` 11%, `remember` 7%, and GC 4.6%. No single hotspot is worth a rewrite.

**V8. MED, effort S. The `npm run bench` village budgets fail on this machine.**
- `packages/human/test/village.timing.ts:50,56`. Run 1: 2325 ms against a 2000 ms budget, and 5144 ms against 5000. Run 2: 3253 and 6483.
- Other agents in this session may have been loading the machine during both runs. I did not confirm an idle baseline.
- The test is also mislabelled. `maxEvents: 1000` caps only the returned array (`sim/sim.ts:784-786`), so the loop always simulates the full 30 days. The doc comment "capped at 1000 events" (`village.timing.ts:28`) suggests the work is capped.
- Fix:
  - Re-baseline on an idle machine, or budget per person-day (~2.5 ms) instead.
  - Fix the comment, or make `maxEvents` break the loop if that was the intent.

**V9. LOW, effort S. `remember` sorts on every call once memory is full.**
- `memory/memory.ts:115-137`: once `maxEpisodes = 200` is reached (~day 20 in the village), every new episode runs `deceasedSet`, then filter + sort + slice over 200 episodes, then a linear scan for the worst one.
- It accounts for 5% self time and 7% inclusive.
- Fix: cache `protectedIds` keyed on episode count + newest id + deceased count, as `episodesByAction` already does (`memory.ts:200-218`).

**V10. LOW, effort S. `advanceMemory` decays all 200 episodes on every tick segment.**
- `memory/memory.ts:176-186`: one `Math.pow` per episode per segment, with segments of at most 60 minutes plus every host `tick`.
- Fix: store `salienceAt` and decay lazily on read (closed form, as the docs already claim for other slices). Alternatively, keep it, since it is 3.7% inclusive.

**V11. LOW, effort S. `stepCommunity` allocates per event.**
- `sim/sim.ts:950-959`: `pendingProposals(c)` filter, plus an array spread per mirror.
- `sim.ts:820-827`: a `heard` filter and a `[...queued, ...heard]` spread per decision.
- `sim.ts:847-853`: an O(n) `nextEventAt` scan per event. Each call runs `awaitingJoint`, which runs `pendingProposals`, which filters again (`sim.ts:383-391`).
- The cost is invisible at n ≤ 200 (see V7). Fix only if hosts go past ~500 people: a min-heap keyed on `nextEventAt`, and a cached pending list.

### Snapshot and save size

**V12. MED (for framework hosts), effort S. The decision `trace` dominates a young person's save.**
- Measured on 10 villagers, person `p00`:

| | JSON size | `trace` | `memory.episodes` | `chronicle` |
|---|---|---|---|---|
| day 1 | 99 KB | 76 KB (77%) | — | — |
| day 200 | 329 KB | 82 KB | 43 KB | 182 KB |

- `trace` is 32 full `DecisionRecord`s at ~2.5 KB each (`person.ts:159` sets `maxTrace: 32`; trimmed at `person.ts:906-907`).
- Everything is bounded: episodes 200 (`memory.ts:30`), chronicle 120 days (`chronicle/chronicle.ts:32`). Size plateaus from ~day 120.
- 10 people come to 3.0 MB of JSON. That is over the ~5 MB localStorage quota by ~17 people.
- `snapshot()` is a bare `structuredClone` (`person.ts:1397-1399`) taking 2.3 ms per person at day 200. `JSON.stringify` of 10 people takes 9 ms.
- Fix: offer `snapshot(p, { trace: false })`, or trim the `considered[]` terms in saved trace entries. Document the expected ~330 KB per person at steady state.

**V13. INFO. The games persist nothing.** `localStorage` holds only two boolean flags (`colony/ui/App.tsx:37,45`, `colony/ui/useColony.ts:59,67`). There is no save, so there is no storage growth or quota risk on the live site. A reload loses the run.

### Game main thread and worker

**V14. INFO (good). The simulation runs off the main thread.**
- Both games run the sim in a Web Worker: `colony/worker.ts`, and `voice/worker.ts` via `voice/ui/transport.ts:7`.
- The page posts `tick` from `requestAnimationFrame` (`useColony.ts:134-142`, `useVoice.ts:122-129`). rAF pauses in hidden tabs, and `dt` is clamped (`colony/sim/playback.ts:23,29`; `voice/sim/game.ts:762`).
- Worker cost per message, measured headless:
  - Voice: `tick` p50/p95 0.04/0.23 ms, max 4.6 ms; `frame()` p50 0.08 ms.
  - Colony: `handle(tick)` p50/p95/p99 0/0.18/0.37 ms.
- Frame payloads:
  - Voice: 9.5 KB median, 15.3 KB max, posted at most every 66 ms (`voice/worker.ts:20,31-32`).
  - Colony: ~6.5 KB, posted on every tick that advances a minute.

**V15. LOW, effort S. The colony worker stalls for 134–224 ms at game end.**
- Measured at minutes 2880 and 4320. `summary()` runs `solo()`, which re-simulates the whole control game synchronously (`colony/sim/game.ts:881-892`).
- This is worker-side, so the UI keeps painting, but frames and input replies queue behind it.
- Fix: advance `soloGame` incrementally alongside play (a few minutes per tick), or run it in the hindsight worker.

**V16. MED, effort S. Voice re-renders the whole React tree about 15 times a second with no memoization.**
- `setFrame` on every frame (`voice/ui/useVoice.ts:89`). There are zero `memo(` calls in `voice/ui/*.tsx`.
- `DayLog`'s `useMemo(() => collapse(log), [log])` (`voice/ui/DayLog.tsx:57`) never hits, because the worker sends a fresh `this.log.slice(-LOG_CAP)` every frame (`voice/sim/game.ts:1857`). As a result `collapse` over up to 300 rows runs on every render.
- `log` is 12 KB of a 15 KB frame and is structured-cloned with every post.
- Fix:
  - Send `log` only when its length or last id changes, with a `logVersion` field, and keep the previous array on the main thread.
  - `memo` `TopBar`, `HalilPane`, `EndsPane`, `VoicesPane` and `Composer`, and pass them frame slices.

**V17. LOW–MED, effort S. Colony also sets React state on every frame.** `setFrame` and `setPlayback` run per frame message (`colony/ui/useColony.ts:141-143`), so `App` re-renders up to ~30 times a second at speed 2.
- `Pane`, `PeopleRows`, `GoalStrip` and `OrderLog` are `memo`'d. `Inspector`, `PaneStats` and `Composer` are not.
- `frame()` also `structuredClone`s the order cards on every frame (`colony/sim/game.ts:846`).
- Fix: version-gate `cards`, and keep `playback` out of state when it has not changed.

**V18. LOW, effort M. The colony canvas redraws the full scene on two canvases every rAF, including while paused.**
- `colony/ui/Pane.tsx:115-136` has no early-out. `drawGround` fills 20×14 tiles one `fillRect` at a time (`colony/ui/renderer.ts:200-232`), then buildings, labels and lantern radial gradients follow, with one gradient created per lantern per frame (`renderer.ts:723-730`).
- Cheap per frame, but a constant battery cost.
- Fix:
  - Cache the ground and static buildings in an offscreen canvas per side and resize, then `drawImage` it.
  - Skip the draw when the frame, hover and selection are unchanged and no weather or night animation is active.

## SUSPICIONS (not confirmed)

- **S1.** Voice `ghost()` (`voice/sim/game.ts:744-749`) `structuredClone`s Halil (~100–330 KB). It is called from `frame()`/`prefillNow` while waking (`game.ts:1783`) and up to twice per `lookAhead` (`game.ts:1056,1070`). In the headless run, `frame()` stayed under 0.8 ms max, so it is likely fine. I did not measure it in a browser.
- **S2.** Main-thread long tasks on a low-end device were not profiled. V16 is the most likely source. Check with a Chrome performance trace at 4× CPU throttle on `/voice/`.
- **S3.** The O(n²) per sim-day shape of the scheduler (V11) did not show up up to n=200. ms per person-day *fell* from 2.6 to 1.48, so treat it as theoretical.
- **S4.** The voice 12-day skip (`advance`) takes ~300–316 ms synchronously in the worker (bench). The "between" screen hides it. It was not checked on mobile.

## Fix order

1. V1 and V2: a three-line `_headers` change, then redeploy and confirm `content-encoding: br` and a clean `Cache-Control` with curl.
2. V3: self-host and trim the fonts.
3. V16: version-gate the voice `log`, and add `memo`.
4. V8: re-baseline or reword the bench.
5. V12: an option to omit the trace from saves.

Everything else is optional.
