# Security review, 2026-10-04

Scope: live site https://human.adamwhite.work (/, /colony/, /voice/, /release.json, assets), `apps/site` build output (the `dist` of abde83c, which is the live release), dependencies, supply chain, client storage, the planned playtest export/import, and full git history (517 commits, archive/v0 included). Read-only review; nothing was changed on Cloudflare or GitHub.

Threat model: a static, single-player site with no accounts, no backend, no cookies and no secrets in the client. Realistic risks are (a) header/CSP hardening, (b) the planned playtest file import treating an untrusted file as trusted state, (c) supply chain at build time, (d) secrets in git history. Nothing found is exploitable today; the top items are hardening and getting the import design right before it ships.

## Verified findings

Severity is for this site's threat model. Effort: S under an hour, M a few hours, L longer.

### V1. `/assets/*` gets contradictory `Cache-Control` (low security, real performance cost; S)
Evidence: `curl -sI https://human.adamwhite.work/assets/main-HNsf69UE.js` returns `cache-control: no-cache, no-transform, public, max-age=31536000, immutable`. Cloudflare merges the `/*` and `/assets/*` rules in `apps/site/public/_headers:1-8`, so the hashed assets also carry `no-cache`, and browsers revalidate them on every load. Same on `/assets/` (404).
Fix: detach the inherited header in the `/assets/*` block with `! Cache-Control` (Workers static-assets `_headers` syntax), then set the immutable value. See the proposed block below.

### V2. No HSTS (low; S)
Evidence: no `strict-transport-security` on any response. HTTP redirects with `301` to HTTPS (`curl -sI http://human.adamwhite.work/`), so only a first visit over HTTP on a hostile network can be downgraded.
Fix: `Strict-Transport-Security: max-age=31536000; includeSubDomains` (this only covers `*.human.adamwhite.work`, not the apex). Add `preload` only if the apex `adamwhite.work` is ever HSTS'd as a whole.

### V3. Missing `Permissions-Policy`, `Cross-Origin-Opener-Policy`, `Cross-Origin-Resource-Policy`, `X-Frame-Options` (low; S)
Evidence: absent from all live responses and from `apps/site/public/_headers`. `frame-ancestors 'none'` already blocks framing in current browsers; `X-Frame-Options: DENY` only covers old ones. The games use no camera, mic, geolocation, payment or USB.
Fix: add the headers in the proposed block. Do not deny `fullscreen` or `screen-wake-lock`: R2 plans mobile fullscreen.

### V4. CSP is looser than the site needs (low; S)
Evidence: live CSP (`_headers:2`) allows `style-src 'unsafe-inline'`, `worker-src blob:`, `img-src blob:` and `font-src 'self'`. The built HTML (`apps/site/dist/{,colony/,voice/}index.html`) has no inline scripts or `<style>` blocks; the bundles contain no `createObjectURL`, `blob:`, `createElement("style")`, `setAttribute("style"`, `cssText`, `insertRule` or `WebAssembly` (grep over `dist/assets/*.js`). React sets `style={}` through the CSSOM, which CSP does not block. Workers load from `/assets/*.js` (same origin).
Tested: I served `dist` locally with the strict CSP below (plus COOP), opened /, /colony/ (pressed Play, the sim ran in its worker) and /voice/ (pressed Begin, the worker ran), with fonts loaded and no CSP violations in the console. 63 elements with React inline styles rendered correctly.
Negative result: adding `require-trusted-types-for 'script'` breaks both games (`Failed to construct 'Worker': This document requires 'TrustedScriptURL' assignment`, at `colony-C_4eFGps.js:1:70688`). Leave Trusted Types out unless you add a policy for the worker URLs.

### V5. Google Fonts loaded from Google on every page (low; M)
Evidence: all three HTML files link `https://fonts.googleapis.com/css2?...` and preconnect to `fonts.gstatic.com`. Every visitor's IP and referrer origin go to Google (a German court fined this in 2022 under GDPR), the stylesheet cannot be pinned with SRI because Google varies it per user agent, and the pages depend on a third party to render as designed.
Fix: self-host the woff2 files (for example `@fontsource-variable/fraunces`, `@fontsource-variable/instrument-sans`, `@fontsource/jetbrains-mono`, `@fontsource/spectral`, as npm deps bundled by Vite), drop the preconnects, then tighten the CSP to `style-src 'self'; font-src 'self'`.

### V6. Planned playtest import: the framework's loader is safe against prototype pollution, but nothing yet validates a whole playtest file (medium for the planned feature, not live; M)
Planned design: HANDOFF.md:16 (R1) and :23 (G3-4) call for an export of "seed + input log + state JSON, replayable" in Games 1–3; the owner asked for a JSON download in `docs/games/playtest-2026-10-04.md:21`. No import or export code exists yet (no `FileReader`, `createObjectURL`, `download` or file input in `apps/site/src`).

What I probed (`node` against `packages/human/src`):
- `restore` (`packages/human/src/person.ts:1449`): a save with top-level `"__proto__"` and `"constructor": {"prototype": ...}` keys, and a `"__proto__"` key inside `needs`, restores without polluting `Object.prototype`; the result's prototype is `Object.prototype`. Object spread (`person.ts:1469`, `fillFrom` at `:1431`) and `structuredClone` create own properties, and `fillFrom` iterates the defaults' keys, not the save's. Good.
- `restore` keeps unknown top-level keys: a 5 MB `junk` string survived into the restored Person, so it would ride along into later snapshots and exports. Numbers are checked only for finiteness: `now = 1e308` is accepted. A name of `<img src=x onerror=alert(1)>` is kept verbatim; harmless today because the UI renders through React text and canvas `fillText`, and `apps/site/src` has no `dangerouslySetInnerHTML`, `innerHTML` or `insertAdjacentHTML`.
- `migrate` (`packages/human/src/migrate.ts:66`) looks up `MIGRATIONS[v]` on a plain object, so inherited names resolve: `engine: "__proto__"` throws `step.apply is not a function` instead of the intended message; `constructor`, `toString` and similar fall through `Function.prototype.apply` and then hit the intended error via the guard. No pollution, but the lookup is wrong in principle. Fix: `Object.hasOwn(MIGRATIONS, v) ? MIGRATIONS[v] : undefined` (also at `:48`) or a `Map`.
- `ColonyGame.replay` (`apps/site/src/colony/sim/game.ts:514-536`) trusts the log: any `kind` that is not `order`, `cancel` or `dismiss` is treated as `continue` (`:530`), `e.input` and ids go to `issue`/`cancel`/`dismissNudge` unchecked, and a non-numeric `minute` silently stops consumption of the rest of the log. The run is bounded by `endMinute`, so a hostile log cannot loop forever.

Recommendations for the import:
1. Check `file.size` before reading (cap at about 2 MB; a three-day colony log is far smaller) and read with `await file.text()` inside `try`/`catch` around `JSON.parse`. No `fetch(blobUrl)`: it would need `connect-src blob:`.
2. Validate an envelope first: `{ schema: 'colony-playtest@1' | 'voice-playtest@1', engine: string, seed: safe integer, log: array (max length, e.g. 10 000) }`. Validate each log entry as a discriminated union with an explicit `kind` whitelist, integer `minute` inside `[0, endMinute]`, non-decreasing order, and ids and inputs checked against the scenario. Reject the file on the first bad entry and name the reason. Write it as one small hand-rolled validator in the site, which keeps the dependency count down; no schema library is needed.
3. Make replay from seed + log the source of truth. Use the exported state JSON only to compare against the replay ("this file reproduces: yes or no"). Do not load it as live state. If state must be loaded, go through `restore` and drop unknown top-level keys (whitelist the Person keys in `restore`, or strip them in the host).
4. Run the import replay in the existing worker pattern (`hindsight-worker.ts`) so a large but valid log cannot freeze the UI, and terminate the worker on navigation.
5. Keep rendering imported strings only through React text or canvas. Add a Biome rule or a test that fails on `dangerouslySetInnerHTML`/`innerHTML` in `apps/site/src`.
6. Export: build the file with `new Blob([JSON.stringify(...)], { type: 'application/json' })` and an `<a download>`. Use a fixed filename pattern (`colony-<seed>-<release>.json`), not player text. Include `release.json`'s commit so a file names the build that made it. The Voice log contains what the player typed; keep the export user-initiated and never upload it automatically.

### V7. localStorage handling is sound (no action)
Evidence: only two keys, `colony.onboarded` (`apps/site/src/colony/ui/App.tsx:30-49`) and `colony.autoPause` (`apps/site/src/colony/ui/useColony.ts:55-68`). Both reads and writes are in `try`/`catch` and compare with `=== '1'` / `!== '0'`, so corrupt or blocked storage falls back to defaults. No JSON is stored, no IndexedDB, no cookies. The Voice game persists nothing. An aside that is not a security issue: `docs/games/watch.md:86` justifies F5 by "Game 2 is live with dawn saves", but the site has no persistent saves, so a live player has no save that 1.6.0 could strand.

### V8. Build output is clean (no action)
Evidence: no `.map` files and no `sourceMappingURL` in `apps/site/dist`; no `/Users/` paths; no `VITE_`, `import.meta.env` or `process.env` strings; the only external hosts in the bundles are Google Fonts, `www.w3.org` (SVG namespace) and `react.dev` (React error links). The dev-only `?mock=1` path is not in the bundle (`URLSearchParams` is absent from `dist`; `apps/site/src/voice/ui/transport.ts:1-5`). `/_headers` and `/.wrangler` return 404. `wrangler.jsonc` publishes only `./apps/site/dist`.
`/release.json` exposes `app`, `framework`, the full commit SHA and `dirty`. That is fine for a private repository (the SHA reveals nothing without repository access). Informational: the `account_id` in `wrangler.jsonc:4` is an identifier, not a credential.

### V9. Dependencies: 0 advisories (no action)
Evidence: `npm audit --omit=dev` and `npm audit` both report `found 0 vulnerabilities` (npm 11.19.1; 8 prod, 183 dev, 190 total).

### V10. Supply chain is tight (no action; one note for the CI step)
Evidence: `package-lock.json` is lockfileVersion 3; all 190 entries resolve to `registry.npmjs.org` except the two workspace links; every registry entry has an `integrity` hash; `npm ci --dry-run --ignore-scripts` is consistent with `package.json`; no git or URL dependencies and no `overrides`. Exact versions are pinned in all three manifests. Packages with lifecycle scripts: `esbuild@0.28.1` and `workerd@1.20261001.1` (`postinstall: node install.js`), both listed in root `package.json#allowScripts`, which npm 11.19 enforces (`npm/lib/utils/allow-scripts-cmd.js`); `fsevents` is in the lockfile as optional but not installed. No `.npmrc`.
Note for HF 2.0's CI (not yet present; no `.github/`): use `npm ci`, pin actions by commit SHA, set `permissions: contents: read`, and keep the Cloudflare deploy token out of CI unless deploys move there.

## Suspicions (not verified)

- S1. Cloudflare zone features add `speculation-rules: "/cdn-cgi/speculation"` and NEL `report-to` headers (Speed Brain and Network Error Logging). These are not from `_headers`. They are harmless, but they mean the zone has settings outside the repo. If CSP reporting is ever added, check that it does not conflict. ## Proposed `apps/site/public/_headers`

Tested locally against the live build (CSP + COOP); the remaining headers are standard and do not affect page behaviour.

```
/*
  Content-Security-Policy: default-src 'none'; script-src 'self'; style-src 'self' https://fonts.googleapis.com; font-src https://fonts.gstatic.com; img-src 'self' data:; connect-src 'self'; worker-src 'self'; manifest-src 'self'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'; object-src 'none'
  X-Content-Type-Options: nosniff
  X-Frame-Options: DENY
  Referrer-Policy: strict-origin-when-cross-origin
  Permissions-Policy: camera=(), microphone=(), geolocation=(), payment=(), usb=(), browsing-topics=()
  Strict-Transport-Security: max-age=31536000; includeSubDomains
  Cross-Origin-Opener-Policy: same-origin
  Cross-Origin-Resource-Policy: same-origin
  Cache-Control: no-cache, no-transform

/assets/*
  ! Cache-Control
  Cache-Control: public, max-age=31536000, immutable
```

After self-hosting fonts (V5), change the CSP to `style-src 'self'; font-src 'self'` and delete the Google preconnects. When adding `/watch/`, nothing here changes unless Game 3 adds new APIs. After deploy, run `curl -sI .../assets/<file>.js` and confirm that `Cache-Control` no longer contains `no-cache`.
