Adversarial review of `main` at e9848b8 (engine 1.6.0). It covers `packages/human` and `apps/site`; `archive/v0/` is ignored. The review is read-only. Sub-agent sweeps were spot-checked: claims I could not confirm are dropped or listed under Suspicions.

Severity is high, med or low. Effort is S (under an hour), M (a few hours) or L (a day or more).

## 0. The gate: `npm run check` was red on this run

**VERIFIED, high, S.** `packages/human/test/village.test.ts:232` ("runs 20 people for 30 days...") has no per-test timeout.
- Run alone it took 2399 ms. In the full `npm run check` (55 files in parallel, other processes on the machine) it hit Vitest's 5000 ms default and failed.
- Result: 610 tests collected, 609 passed, 1 timed out. It passes when run alone.
- The 50-person test next to it already has `}, 30_000)` (line 246), and the long town tests have `60_000` (town.test.ts:414, 553, 858).

- **Fix:** add `}, 30_000)` to line 232, or move the run to `npm run bench`. Also consider setting `testTimeout` in `vitest.config.ts`, so that heavy simulation tests are not judged by wall-clock time under load.

## 1. Architecture boundaries

**1a. VERIFIED, high, M. Game 2 content is shipped inside the framework, and engine versions are bumped for game edits.**
- `packages/human/src/scenarios/town.ts` has 1363 lines and 191 matches for Halil, Selin, Osman, cigarette or smoking.
- Examples: line 4 (Halil "with hypertension, a cigarette habit"), lines 99-103 (Halil's cigarette cues, "the doctor's walk"), and lines 238-243 (`doctorSaid`, `lastWalk`, `lastAte` on `TownState`).
- It is exported from the public entry (`index.ts:99`, `export * from './scenarios/index.ts'`) and consumed only by `apps/site/src/voice/sim/game.ts:19,51,148-158`.
- `docs/framework.md` (ENGINE_VERSION 1.5.0 entry) shows the engine version was bumped for "Town scenario: Halil's cigarette has no place...". As a result, a game-balance edit invalidates every consumer's saves.

- **Fix:** move `town.ts` (and its tests) to `apps/site/src/voice/sim/`. Keep `village.ts` as the small reference host, and stop versioning the engine for scenario edits. Scenario state gets its own version, if it needs one.

**1b. VERIFIED, low, S.** `narrate/lexicon.ts:30` contains the default line "Thirsty — the well, then." This is Game 1 scenery in framework default text. **Fix:** make it neutral ("Something to drink first.").

**1c. VERIFIED, med, S. The published entry point is never exercised by `npm run check`.**

  - `apps/site/vite.config.ts:10`

  - `apps/site/tsconfig.json:10`

**1d. VERIFIED, OK.** All 19 site imports use the bare `@human/framework` specifier. There are no deep imports into framework internals.

## 6. Type safety

Counts cover non-test code only:
- `any`: 0. `@ts-ignore`/`@ts-expect-error`: 0. Non-null `!`: 0.
- `biome-ignore`: 3, each justified (`voice/ui/DayLog.tsx:62`, `Composer.tsx:82`, `parts.tsx:58`).

- Plain `as T`: 61 in the framework and 52 in the site.

The holes worth fixing (VERIFIED, med, M overall):
- **`list[i] as T` used to dodge `noUncheckedIndexedAccess`:** `memory/memory.ts:324,326`, `will/will.ts:249,251,1389,1390`, `colony/ui/renderer.ts:135-142`. These defeat the flag the repo opted into. **Fix:** iterate with `for…of` or `entries()`, or guard with `if (!x) continue`.
- **`PLACES.find(...) as Place`** (`colony/ui/renderer.ts:108`) hides a missing place as a later crash. **Fix:** throw with the id.
- **`s.appeal as NeedId`** (`cognition/cognition.ts:254`) accepts any host string as a need. **Fix:** an `isNeedId` guard. Check whether `urgencyOf` tolerates unknown keys.
- **About 22 `as VillagerId` casts in `colony/sim/human-world.ts`** (325, 707, 733, 764, 786, 804, 996, 1081, 1103, 1108, 1141, 1162, 1239, 1258, 1289, ...). **Fix:** narrow once at the adapter boundary with an `isVillagerId(id): id is VillagerId` guard.
- **`isVoiceId` is not a type predicate.** `voice/sim/prefill.ts:147` casts right after calling it, and `game.ts:1902` and `view.ts:66` do the same. **Fix:** declare it as `(id: string): id is VoiceId`.
- **`Object.keys(x) as NeedId[]`**, about 10 times in `memory.ts` and `cognition.ts`. This is standard and low risk, but a typed `keysOf` helper in `core/` would centralise it.
