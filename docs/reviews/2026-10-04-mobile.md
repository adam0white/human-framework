# Mobile web review, 2026-10-04

Reviewer: adversarial mobile-web pass (phase R2). Scope: `apps/site` home, `/colony/` (Twice at the Well), `/voice/` (The Day You Say Nothing), live at https://human.adamwhite.work, as deployed on 2026-10-04.

**What the evidence is.** I read the code, and I loaded the live site in headless Chromium (Playwright) with an emulated mobile viewport, touch, DPR 3 and a Samsung Chrome user agent. Viewports were 360x690 (S26 portrait with the Chrome toolbar; the height is my estimate), 384x740, 760x300 (S26 landscape, estimated) and 891x350 (S26 Ultra landscape, estimated). This is **not** Samsung Internet and **not** a device. Layout arithmetic and measured element sizes carry over to a real phone. Gesture behaviour (pull-to-refresh, pointercancel, double-tap zoom) does not, so those findings are marked SUSPICION. Screenshots are in the session scratchpad and were not committed.

**Consequence for these games.** Both game roots are fixed at `100dvh` with `overflow: hidden`, so the document never scrolls. On Chrome, Samsung Internet and Safari, that means the toolbar **never collapses**. The game loses about 56 CSS px on Android, and on iOS about 96 px in Bottom tab-bar mode or about 36 px in Compact mode (754 minus 658, and 754 minus 718), for the whole session. `dvh` cannot recover that space. Only fullscreen (Android) or a Home Screen web app (iOS) can.

### A3. Platform support, 2026

- **Fullscreen API.**
  - Chrome Android and Samsung Internet support `element.requestFullscreen()`.
  - iPhone Safari does not support it for non-video elements. Only `video.webkitEnterFullscreen()` works ([caniuse](https://caniuse.com/fullscreen) shows iOS as "partial" through 27.2; [WebKit bug 212934](https://www2.webkit.org/show_bug.cgi?id=212934)).
  - iPad has element fullscreen from 16.4 (unconfirmed, search snippet only).
  - It must be called from a user gesture.
- **Screen Wake Lock.** Chrome Android and Samsung Internet 14+ support it. iOS Safari supports it from 16.4, and Home Screen web apps were fixed in 18.4 ([caniuse](https://caniuse.com/wake-lock), [WebKit 18.4](https://webkit.org/blog/16574/webkit-features-in-safari-18-4/)). The lock is released whenever the page is hidden, so re-acquire it on `visibilitychange`.
- **`touch-action`.** Full support on iOS 13+ and Chromium. `manipulation` disables double-tap zoom ([caniuse](https://caniuse.com/css-touch-action), [MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/touch-action)). iOS 10+ ignores `user-scalable=no` and `maximum-scale` ([MDN](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/meta/name/viewport)), so `touch-action` is the only lever on iOS.
- **`overscroll-behavior`.** iOS 16+, Samsung 8.2+, Chrome 65+ ([caniuse](https://caniuse.com/css-overscroll-behavior)). Setting `none` on `html` and `body` turns off Chrome's pull-to-refresh.
- **Viewport meta.** `viewport-fit=cover` plus `env(safe-area-inset-*)` is broadly supported ([MDN env](https://developer.mozilla.org/en-US/docs/Web/CSS/env)). `interactive-widget` works in Chrome and Samsung 21+, not iOS ([caniuse](https://caniuse.com/mdn-html_elements_meta_name_viewport_interactive-widget)). It is not applicable here (see B3).
- **`dvh`/`svh`/`lvh`.** iOS 15.4+, Samsung 21+, Chrome ([caniuse](https://caniuse.com/viewport-unit-variants)).
- **`screen.orientation.lock()`.** Supported in Chrome and Samsung Internet. No Safari version supports it ([caniuse](https://caniuse.com/mdn-api_screenorientation_lock)). In Chrome it requires fullscreen; that is from memory, unconfirmed. On iPhone, layouts must handle both orientations.
- **Manifest `display`.**
  - The fallback chain is fullscreen, then standalone, then minimal-ui, then browser ([MDN](https://developer.mozilla.org/en-US/docs/Web/Manifest/display)).
  - Safari 26 opens Home Screen sites as web apps by default ([WebKit 26.0](https://webkit.org/blog/17333/webkit-features-in-safari-26-0/)).
  - Whether iOS honours `fullscreen` rather than `standalone` is unconfirmed; assume `standalone`.
- **Pointer events.** iOS 13.2+, Samsung 6.2+, Chrome 55+ ([caniuse](https://caniuse.com/pointer)).
- **Text selection and long-press.** `-webkit-touch-callout` is iOS only ([caniuse](https://caniuse.com/mdn-css_properties_-webkit-touch-callout)). Keep the `-webkit-user-select` prefix for Safari ([caniuse](https://caniuse.com/user-select-none)).
- **Hit targets.** WCAG 2.2 SC 2.5.8 (AA) sets a 24x24 CSS px minimum, with a spacing exception ([W3C](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)). Apple recommends 44 pt and Material 48 dp ([TetraLogical](https://tetralogical.com/blog/2022/12/20/foundations-target-size/), secondary source).

### B2. Detail and fixes

**1. Colony in landscape: no maps.**

- The phone branch applies at 860 px and below, regardless of height.
- In landscape the fixed rows take 48 + 40 px (`:2158`). The centre column is `flex: 0 0 var(--phone-center-h)`, where `--phone-center-h` is `clamp(304px, 40dvh, 336px)` and so at least 304 px (`:2677`, `:2723`). That totals 392 px before the maps get anything.
- The panes are `flex: 1 1 0; min-height: 0` (`:2680-2683`), so they absorb the whole deficit and shrink to zero.
- The older `flex: 0 0 30dvh` at `:2298` is overridden by `:2680`. Fix the later rule.
- Fix: add a landscape-phone branch that lays the stage out as a row. Put the centre column on one side and **one** map at a time on the other, with a Classic/Human toggle. Two side-by-side maps at 300 px tall each come to about 430x300, which does not fit next to a 280 px composer in 780 px.

```css
@media (max-width: 1180px) and (max-height: 500px) and (orientation: landscape) {
  .colony { grid-template-rows: 40px minmax(0, 1fr); padding-inline: env(safe-area-inset-left) env(safe-area-inset-right); }
  .goal-strip { display: none; }            /* or fold into the topbar */
  .stage { display: grid; grid-template-columns: minmax(0, 1fr) 280px; grid-template-rows: minmax(0, 1fr); }
  .center { flex: none; order: 2; overflow-y: auto; }
  .pane { min-height: 0; order: 1; }
  .stage:not(.show-human) .pane-human, .stage.show-human .pane-classic { display: none; }
}
```

The toggle is a small piece of new React state. The `max-width: 1180px` bound also catches the S26 Ultra and the 17 Pro Max in landscape (finding 8).

**2. The maps cannot be tapped reliably.**

- At 360x690 each map is 213x149 CSS px for a 640x448 logical map, a scale of 0.333 (`toLogical`, `Pane.tsx:212-218`).
- One 32 px tile is about 10.7 CSS px.
- `hitPerson` uses 18 logical px (`Pane.tsx:63`), about 6 CSS px of radius, so the target is about 12 px across. That is half the WCAG minimum, and villagers stand one or two tiles apart.
- The cause is height, not width. The 304 px centre minimum and the 104 px stats column (`colony.css:2688`) leave the canvas about 149 px tall.
- The villager and place rows already give a full touch path, so the map is optional input. But the copy says "Pick a villager here or on either map."
- Fix, in two parts:
  - (a) Scale the touch radius to at least 22 CSS px.

    ```ts
    const r = (e.currentTarget as HTMLElement).getBoundingClientRect();
    const minLogical = (22 * LOGICAL_W) / r.width;              // 22 CSS px
    const radius = e.pointerType === 'touch' ? Math.max(18, minLogical) : 18;
    // pass radius into hitPerson; it already picks the nearest within radius
    ```

  - (b) On portrait phones, give the space to one map. Use a Classic/Human toggle in place of two stacked 149 px maps; one full-width map is 360x252 at a scale of 0.56. Alternatively, move the stats column above the map so the canvas can use the full 360 width.
  - If neither lands, change the phone copy to "Pick a villager here."

**3. Pull-to-refresh and reload lose the run.**

- Only `AUTO_PAUSE_KEY` and `ONBOARDED_KEY` are persisted (`useColony.ts:59-67`, `App.tsx:37-45`). Voice persists nothing. A reload restarts the game.
- `html` and `body` set no `overscroll-behavior` (`theme.css:93-105`).
- Chrome Android starts pull-to-refresh from a downward drag at scroll-top. I expect this on a non-scrolling document, but did not verify it on a device. A drag on the topbar or the voice log would then reload the page.
- Fix (S):

  ```css
  html, body { overscroll-behavior: none; }
  ```

- The longer-term fix (M) is to save the orders log and seed to `sessionStorage` on `visibilitychange` → hidden. The sim is deterministic, so replaying the orders restores the run. Android also discards background tabs, and the game is lost the same way.

**4. Voice topbar overlap.**

- At 767 px and below, `.v-top` is `minmax(0,1fr) auto` (`:1864-1870`).
- `.v-top-id` has `min-width: 0` (`:252`) but no `overflow: hidden`. `.v-top-day` (1.12 rem display serif, `:267-270`) does not shrink, so "Ramadan 1" runs 30 px under Play at 360 wide. "Ramadan 29" is wider still.
- Fix:

  ```css
  @media (max-width: 767px) {
    .v-top-id { overflow: hidden; }
    .v-top-day { font-size: 1rem; white-space: nowrap; overflow: hidden; text-overflow: clip; }
    .v-top-controls .v-btn-play { width: 40px; }   /* or drop "Slow" into an overflow menu */
  }
  ```

- A cleaner layout gives the topbar a two-row id at 400 px and below: day and time on the left, and the speed controls on the sky row.

**5. Fullscreen (Android).**

- Add a "Full screen" item to the colony `…` menu and to the voice topbar, shown only when `document.fullscreenEnabled`. That excludes iPhone.

```ts
const goFull = async () => {
  try { await document.documentElement.requestFullscreen({ navigationUI: 'hide' }); } catch {}
  try { await (screen.orientation as any).lock?.('portrait'); } catch {}   // optional, Chrome only
};
```

- Pick one orientation policy. If phones are portrait-only, the S path is the lock plus a "rotate your phone" overlay under `(max-width: 860px) and (orientation: landscape)` (the lock does nothing on iPhone). Otherwise drop the lock and build the M landscape layout from finding 1. I recommend the landscape layout, since landscape is the natural orientation for a two-map game.
- The game should also offer it once on the first Play tap on touch devices (`matchMedia('(pointer: coarse)')`). Do not force it.

**6. Wake lock.**

```ts
useEffect(() => {
  if (!running || !('wakeLock' in navigator)) return;
  let lock: WakeLockSentinel | null = null;
  const get = async () => { try { lock = await navigator.wakeLock.request('screen'); } catch {} };
  const onVis = () => { if (document.visibilityState === 'visible') get(); };
  get(); document.addEventListener('visibilitychange', onVis);
  return () => { document.removeEventListener('visibilitychange', onVis); lock?.release(); };
}, [running]);
```

Hold the lock only while the clock runs. Release it on pause and on the end screen.

**7. Safe areas.**

- In colony, `.colony` pads only the bottom at 860 px and below (`:2156`), and the topbar has no top inset.
- Neither game pads left or right. With `viewport-fit=cover`, an iPhone in landscape puts the clock or title under the island, and a Home Screen web app puts the topbar under the status bar.
- Fix:

  ```css
  .colony { padding: env(safe-area-inset-top) env(safe-area-inset-right) env(safe-area-inset-bottom) env(safe-area-inset-left); }
  ```

- Scope this to the phone branch, or use `max(16px, env(...))` for the inline sides; unscoped, it would wipe the desktop `padding: 0 16px 12px`. Do the same for `.voice`, keeping its existing top and bottom `max()` rules.

**9. Manifest.**

- Add `public/manifest.webmanifest` with `{"name":"Human Framework","start_url":"/","display":"standalone","background_color":"#12152a","theme_color":"#12152a","icons":[192,512 PNG]}`.
- Add `<link rel="manifest">` and `<link rel="apple-touch-icon" href="/icon-180.png">` to all three HTML files.
- The CSP `default-src 'self'` already covers `manifest-src`.
- Per-game `start_url` (`/colony/`, `/voice/`) needs separate manifests if each game should install on its own.

**10-17. One-liners.**

- 10: `.bubble { min-height: 28px; padding-block: 7px; }` on touch, or add `::after { inset: -6px }` to enlarge the hit area.
- 11: raise to 0.7 rem or more and let the clock status ellipsize.
- 12: `.pane-canvas { touch-action: none; }`. The map neither zooms nor pans, and this also stops pull-to-refresh starting on it.
- 13 and 14:

  ```css
  html { -webkit-tap-highlight-color: transparent; }
  body { touch-action: manipulation; }
  ```

  Keep visible `:active` states.
- 15: `Math.min(devicePixelRatio, 3)`.
- 16: add `-webkit-user-select: none`.
- 17: `.nav nav a { padding-block: 12px; }`.

### B3. Not applicable or no action

- **Virtual keyboard and `interactive-widget`.** Neither game has a text input. The only `<input>` is a checkbox (`parts.tsx:210`). The keyboard never opens, so no change is needed.
- **`setPointerCapture`.** The canvas handlers act on `pointerup` over the canvas. A drag that leaves the canvas simply does nothing, so capture is not needed.
- **Home page.** It scrolls normally, has no horizontal overflow at 360, and no `viewport-fit=cover` is needed.

## Summary

- **S26 (base):** 1080x2340 physical, FHD+ only. CSS viewport 360x780, DPR 3. Chrome visible area is about 360x690 with the toolbar, which never hides here (estimate). Landscape is about 780x300 (estimate). Samsung Internet toolbar heights were not found.
- **S26+ and Ultra:** 384x832 (unconfirmed) and 412x891 CSS. DPR is about 2.8 and 2.6 at the default FHD+ setting (inferred).
- **Top gaps:**
  1. Colony landscape on phones renders no maps (0x0). The 304 px centre minimum starves flex panes. High, M.
  2. Colony portrait maps are 213x149 px, with villager hit targets about 12 px across. Scale the touch radius to 22 px or more, and show one map at a time. High.
  3. No `overscroll-behavior` on the root and no saved state. One stray pull-down or a tab discard restarts the game. High, S for the CSS.
  4. The voice topbar day label overlaps the Play button at 360 to 384 wide. Med, S.
  5. No fullscreen (Android), wake lock, manifest or apple-touch-icon. The toolbar permanently costs about 56 px (Android) and about 96 px (iOS Bottom mode) or 36 px (Compact), and the screen dims mid-sim. Med, S each.
  6. Top, left and right safe-area insets are missing despite `viewport-fit=cover`. Med, S.
