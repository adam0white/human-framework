# Executable coverage and research boundaries

Snapshot: 2026-09-07, engine 0.2.0. This ledger describes the current [kernel](../src/core/index.js), [scenario data](../src/scenarios/index.js), and [experiment runner](../src/experiments.js). It narrows the broader [framework proposal](framework-proposal.md); responsibilities listed in that proposal are not evidence that their mechanisms have been implemented.

**Implemented** means an executable transition, interface, or record exists. **Proxy** means an implemented quantity or rule is an authored engineering approximation without human calibration. **Unmodeled** means the kernel supplies no mechanism for that function. A proposed interface below is a research design, not an existing plugin API. A rejection test states what would count against adding a mechanism or making the associated claim.

## Where computation closes

An engine-created state, supported scenario, valid configuration, seed, and sequence of supported commands are enough to compute a run without an LLM or external service. Actions have five kinds: `work`, `rest`, `eat`, `observe`, and `help`. Commands either delegate a round or supply one actor's action; every actor acts once in stable order, followed by shared clock advancement and consumption. Execution can fail after an admissible attempt consumes time and resources. The replay manifest records the scenario, options, commands, and engine version.

This is computational closure **within the supported schema**, not coverage of every situation a human can encounter. Unknown action kinds, command types, action/actor references, task skills, policies, and module keys are rejected. Invalid finite-value ranges and incompatible replay versions are rejected. Extra JSON metadata may be retained, but adding a field named `emotion`, `worship`, or `intelligence` does not give it causal behavior. Arbitrary state edits outside the command interface are not a documented replay intervention protocol. See the [API contract](mvp-spec.md) and [validation code](../src/core/model.js).

Courier Crossing, Repair Bench, and Water Commons reuse the same kernel without scenario-name branches. All three have the same aggregate-task structure: two actors make contributions toward one shared target while managing body proxies, a hidden scalar hazard, and shared rations. Commons adds recurring consumption. Solo Repair is the fourth preset and removes peers, promises and help; social ablations have no effect in that control. This demonstrates data reuse within that structure. It does not yet demonstrate route navigation, tool/material contention, bargaining, ownership, or reuse across fundamentally different game mechanics.

## Bodily and cognitive coverage

| Responsibility | Current executable coverage and limit | Proposed interface and rejection test |
|---|---|---|
| Body and action capacity | **Proxy.** Bounded fatigue/hunger accumulate with simulated minutes; work/help add effort, rest recovers fatigue, and a ration reduces hunger. A shared capacity guard checks full exertion cost and explicitly substitutes recovery when the fatigue/hunger ceiling would be crossed. A logistic rule combines skill, difficulty, body, hazard exposure, and assistance into work success. No metabolic units, sleep, pain, injury, disease, sensory organs, or motor control. | A duration-aware body transition could supply task-specific capacity and observations. Add detail only if it distinguishes measured responses that the coarse model misses. Reject a universal “energy” quantity presented as a physiological measurement without calibration. |
| Perception and access to information | **Implemented projection; proxy sensing.** `getView` excludes hidden hazard, replay seed, and other actors' private weights/intentions. It exposes rounded body estimates, public task descriptions, and peer state. Paid inspection produces a noisy report; survey proficiency affects its noise. Disabling belief learning removes stored hazard updates and inspection information value together; it does not implement a learned stopping rule. No vision, hearing, spatial occlusion, or general testimony system. | Give observations explicit channel, observer, source, and cost. Changing inaccessible world facts must not change a policy's choice before accessible evidence or effects differ. A renderer's diagnostics are not permissible NPC input. |
| Attention and working capacity | **Unmodeled.** Ranking reads the accessible fields directly. Inspection's time cost is not an attention bottleneck, and displaying recent events does not establish working-memory capacity. | A cue-selection or bounded-buffer mechanism should predict errors under distraction or load. Reject it if the same choices follow from simpler observation-access rules or if it silently grants extra information. |
| Beliefs, understanding, and metacognition | **Proxy beliefs; unmodeled general understanding.** One hazard estimate is blended with inspection reports. Confidence increases by a skill-dependent heuristic. This is not full Bayesian inference, probability calibration, causal discovery, or reasoning about another mind. The trace's `understand` phase formats body/resource facts; it does not execute a separate comprehension process. | Compare explicit belief-updating and planning alternatives on misleading, redundant, and changing evidence. Reject a claim of improved understanding based only on higher internally generated confidence or a phase label. |
| Memory and knowledge | **Audit records and persistent state only.** Hazard belief, proficiency, a promise, directed trust, support, and last action persist. `history` is an audit log, not episodic memory. The actor view contains recent public outcomes, but the default ranking policy does not retrieve or reason over that list. No semantic knowledge base, autobiographical recall, or forgetting/retrieval mechanism. | An actor-owned memory interface should store only experienced information and expose bounded retrieval. Test a delayed-cue task with cue removal against a memory-free comparator; reject “memory benefit” when the answer remains directly visible. |
| Learning, retention, and transfer | **Proxy.** Work and inspection produce bounded task-proficiency gains, including failed work attempts. Authored directed transfer links carry provenance and do not recurse; all presets use zero transfer. The exported `retain` helper exists, but the simulation does not call it: no ongoing forgetting is implemented. | Compare equal-duration practice of A, active practice of B, and idle time, then test trained and untrained tasks. Distinguish temporary performance strain from stored proficiency. Reject unpracticed gains, recursive transfer credit, or general-intelligence claims from task practice. |
| Reasoning, planning, and imagination | **Proxy choice rule; other functions unmodeled.** The full policy scores immediate authored considerations with limited deadline terms. The baseline uses a simpler output/proficiency score. Neither searches action sequences, invents actions, solves arbitrary problems, or imagines counterfactual worlds. | A planner should compete behind the actor-view/choice boundary under an explicit computation budget. Reject added search if its advantage comes from hidden-state access, a larger action set, or special retuning for each scenario. |

The executable owners are [observation.js](../src/core/observation.js), [policy.js](../src/core/policy.js), and the body, sensing, learning, and resolution rules in [simulation.js](../src/core/simulation.js). Their numerical coefficients remain engineering choices.

## Motivation, action, and social coverage

| Responsibility | Current executable coverage and limit | Proposed interface and rejection test |
|---|---|---|
| Motives, needs, and preferences | **Proxy.** Fixed authored `duty`, `care`, `caution`, and `mastery` weights combine with body, expected task contribution, uncertainty, and promise urgency. These are not measured personality traits or a complete needs taxonomy. No dynamic goals for status, belonging, play, sexuality, beauty, or life purpose. | Add a motive only when a declared conflict/task requires it. Test whether different weights and simpler thresholds explain the same behavior. Reject claims that a fitted utility coefficient reveals a person's ultimate values. |
| Commitments and meaning | **Implemented promise record; proxy weighting.** Each actor may have one public promise to attempt a particular action by a due round. Fulfillment/expiry persists and can affect trust. Fulfillment does not require successful output. No promise negotiation, revision, hierarchy, long-term vocation, or life narrative. | Add explicit commitment creation, conflict, release, and revision events. Test competing obligations and infeasible attempts. Reject interpreting kept-promise counts as comprehensive integrity or meaning. |
| Emotion and regulation | **Unmodeled.** Caution and care weights are not fear, love, grief, anger, or emotion regulation. The loop has no separate affect state, coping process, or stress-response model. | Event appraisal could propose a time-bounded affect state with a declared owner for its effects. Reject double-counting existing body/risk terms or adding emotion names that make no discriminating prediction. |
| Choice, intention, and agency | **Implemented request/execution separation.** A valid supplied choice overrides the ranking and is recorded with its source and optional intention text. Insufficient physical capacity can substitute an explicitly recorded recovery interval. Intention text does not manufacture output or alter physical success. This contract does not establish consciousness or settle metaphysical freedom. | Keep choice providers separate from execution. Test two admissible choices from the same state and identical actions with different stated intentions. Reject a controller that silently replaces a difficult or disfavored choice, or credits an unexecuted request with work or practice, or treats stochasticity as proof of free will. |
| Relationships and social actions | **Proxy.** Directed trust changes after public promised attempts/expiry. `help` prepares support for a peer's next work attempt; perceived need guides the recipient. It has no request, acceptance, refusal, deception, conflict resolution, coercion, attachment, reputation network, or theory of mind. | Introduce structured offers/requests and independent recipient responses. Test hidden obstruction versus deliberate noncooperation with matched evidence. Reject an observer's ability to infer private motives from indistinguishable outcomes. |
| Language and narrative | **Deterministic formatting only.** Labels, supplied intention strings, and phase/outcome templates describe structured records. No language understanding, dialogue planning, semantic inference, or narrative agent updates the world. | A future command compiler could propose validated structured actions; it must retain ambiguity or reject unsupported requests. Reject prose that silently creates state, capabilities, or facts. An optional LLM adapter must not become necessary for headless execution. |
| Habits, character, and development | **Unmodeled beyond the updates above.** There is no cue-linked habit learning, inhibition training, reflection, regret, repair sequence, or developmental trajectory. Practice increments are not character formation. | Add explicit repeated-context and repair tasks before a habit/development mechanism. Test changed cues and opportunities as well as repetition. Reject equating behavior frequency or task proficiency with virtue. |
| Creativity and conscious experience | **Unmodeled.** No generative invention, humor, dreams, subjective awareness, or experience is established by the trace. | Operationalize a bounded creative task if useful, separately from claims about experience. Reject “emergence” as evidence of consciousness merely because the output is surprising or narratively plausible. |

## Islamic commitments and normative boundaries

The research starts from Islam as true, with Sunni Hanafi–Maturidi interpretation as the initial scholarly program. That commitment concerns what the project seeks to understand and how it handles personhood, accountability, purpose, and sources. It is not authenticated by the toy engine's results. The [Islamic foundations memo](../research/islamic-foundations.md) separates revealed text, interpretation, empirical claims, and implementation choices; the [historical audit](../research/historical-source-audit.md) rejects inherited sacred-variable equations.

**There is currently no normative or fiqh evaluator.** The kernel does not judge permissibility, obligation, sincerity, repentance, divine acceptance, or ultimate standing. Promise weights are authored reasons for action. Private intention is a recorded string, not a verified inward state. The engine has no scalar for qalb, nafs, ruh, fitrah, faith, spiritual health, or salvation, and no mapping that identifies its ranking function with ʿaql. These absences are limits of implementation, not claims that the theological referents do not exist.

A future reviewed scenario could positively represent worship, truth-seeking, service, hope, love, repentance, or a conflict between advantage and understood duty. It would need distinct records for the sourced normative reference, the character's understanding, chosen intention, observable action, and consequences. This interface is proposed. Its rejection tests are concrete: success cannot establish divine approval; distress cannot establish deficient faith; an observer cannot infer sincerity without evidence; and an unresolved contextual ruling must remain unresolved. No formula for divine judgment is an eligible extension. The restraint and intention distinctions are discussed with their textual sources in the [foundations memo](../research/islamic-foundations.md), including [Qur'an 17:85](https://quran.com/17/85) and [Bukhari 1](https://sunnah.com/bukhari:1).

## Scale, embodiment, and presentation directions

| Direction considered | Current boundary | Gate for further work |
|---|---|---|
| Detailed physiology, inheritance, genetics, and lifespan | **Unmodeled.** Initial conditions are authored; no genome, parentage, aging, reproductive system, or clinical model. | Select a task where a specific mechanism changes an independently measurable outcome. Reject importing population heritability as an individual's genetic percentage, or physiology detail that only reproduces a coarse proxy at greater cost. See the [historical audit](../research/historical-source-audit.md). |
| Adaptive or metagame UI | **Basic viewpoint separation only.** Actor views and researcher diagnostics are distinct. No player-learning model, knowledge-dependent command vocabulary, or persistent metagame progression. | Compare what users can correctly infer and choose with each presentation while holding simulation inputs fixed. Reject diagnostics leaking into character policy or readability/accessibility being mistaken for a cognitive mechanic. |
| Non-pausing or contracting time | **Explicit rounds only.** Simulated minutes advance through `step`; wall-clock waiting is not a bodily process. No guarantee that time continues during inactivity, suspension, or save/load. | Define a wall-clock adapter, minimum rate, interruption, suspension, and replay rules before implementation. Equivalent simulated input histories must remain reproducible regardless of animation speed. |
| Social macro patterns and cliodynamics | **Unmodeled.** Shared depletion is not an institution, economy, culture, or civilization. The schema permits more actors than the two-actor presets, but actor count alone supplies none of those mechanisms. | Choose one bounded aggregate pattern, explicit networks/institutions, competing micro explanations, and independent historical/observational evidence. Reject extrapolating a two-person trust rule into validated cohesion or societal cycles. See [prior art and macro boundaries](../research/prior-art-mvp.md). |
| Quarks or microphysics as a route to people | **Rejected implementation direction for this framework.** No physical substrate simulation exists. | More microscopic detail must earn its place through a needed observable consequence and a tractable model. Merely being a lower-level description does not supply a usable explanation, computational budget, or test of human behavior. |

## Candidate discriminating experiments

These are proposed experiments, not completed acceptance claims. The [benchmark report](benchmark-report.md) records the executed comparison and its limits. Following the [2026-09-07 direction review](post-mvp-review.md), the [roadmap](roadmap.md) places value/units repair and a host-owned game integration before these faculty expansions. The list below is a research menu, not a competing delivery order; a new social task alone does not prove host independence.

1. **Test information seeking beyond a fixed hazard.** Compare the current inspection policy, a simple stopping rule, and a simple threshold policy across redundant, misleading, and changing reports. Keep observation access, cost, and body dynamics matched. Record belief error, inspections, task outcomes, and why inspection stops. The historical 0.1 frozen-belief ablation repeated inspections; 0.2 fixes that score/update mismatch by disabling information value together with updates. This is not yet a learned stopping rule or an isolated estimate of a human faculty's benefit.
2. **Test reuse beyond aggregate-progress tasks.** Add one small structured offer/request task with independent acceptance/refusal and an evidence-limited partner model. Freeze existing body and learning rules before transfer. Measure required schema/kernel changes and compare a simple partner policy. If reuse requires rewriting the shared mechanisms, report that rather than counting another theme as generalization.
3. **Separate learning from output and retention.** Use trained-task, active-control, and idle conditions with equal durations; test an untrained skill and a delayed retest. Keep temporary body impairment separate. Decide explicitly whether a retention transition belongs in the runtime; the existing helper alone is not evidence of a simulated retention process.
4. **Measure tradeoffs under comparable exposure and parameter ranges.** Add a specified fixed-duration follow-up protocol instead of comparing only unequal early-stop endpoints. Vary uncertainty, scarcity, action costs, and authored coefficients; record cases where rankings reverse or mechanisms have no effect. Report task success, time, body costs, and promises separately. Do not tune the full policy until it wins.
5. **Require external evidence before human-validity claims.** Select one population and bounded task; specify observed choices/errors/timing, data provenance, calibration/evaluation separation, and simpler competing explanations before fitting. Synthetic checks establish software behavior. Matching outputs generated by this engine cannot validate the human mechanisms that generated them.

Additional physiology, cognitive modules, religious scenario evaluation, presentation experiments, and macro scale should follow the failures these tests reveal. No coverage percentage or claim of a complete human model follows from this ledger.
